# M5 预览组件选型：Lichtblick 自托管与机器人侧 Foxglove WebSocket

- 对应：`.scratch/m5-live-preview/map.md`（D1 只在工作站本机看、D2 用户目录装 relay 不用 sudo、D3 嵌 Lichtblick）
- 调研日期：2026-11-09。版本号和日期都以这一天为准。
- 做法：Claude 子 agent 联网只读调研（Codex 的联网搜索当天返回空白，按 `codex-workflow.md` 3.0 第 5 条换人），浅克隆 Lichtblick v1.30.0 和 foxglove-sdk（`ros-v3.6.3`、`sdk/v0.30.3`）读源码，下载并核对了 Lichtblick 网页包。没有连接机器人（负责人："机器人正在做rollout"），没有安装任何东西。
- 标 **[已核]** 的条目由执行线另外打开来源重查过（GitHub releases API、PyPI JSON、rosdistro、Lichtblick 源码）。

## 结论速览

1. **机器人侧推荐一个进程**：一个 rclpy 节点直接用 Foxglove SDK（PyPI `foxglove-sdk`）开 WebSocket 服务器，不装 foxglove_bridge。只要装一个 wheel，不编译、不用 sudo；按通道订阅回调，没人看就不干活。JPEG 和 JointState 可以原样转发 CDR 字节，只有头部 H.264 要换成 CompressedVideo 的外壳。
2. **Lichtblick 用发布页现成的网页包**，平台同源挂在 `/lichtblick/` 下。可以完全离线运行。用 URL 参数直接连数据源、加载布局。
3. **不连机器人也能先验证大半**：在工作站上把已有的 R1 Lite MCAP 录制回放成 Foxglove WebSocket 服务器，用本机 Lichtblick 看头部 H.264、腕部 JPEG 和关节曲线。
4. **建议锁定的版本组合**：Lichtblick 1.30.0 + foxglove-sdk 0.30.3（机器人和工作站用同一版）；工作站离线回放另用 mcap 1.6.0 + mcap-ros2-support 0.6.0。这些都是新依赖，要负责人批准（AGENTS.md 规则 7）。

**两种做法的比较**（子 agent 的判断，执行线同意）：

| | (i) foxglove_bridge + rclpy relay | (ii) 一个 rclpy 进程直接用 Foxglove SDK |
|---|---|---|
| 安装（不用 sudo） | 要 colcon 编 C++，缺 rapidjson-dev 头文件时还得想办法 | 装一个 wheel |
| 进程 | 2 个，`/viz/*` 多走一遍 DDS | 1 个 |
| CPU | relay 的 Python 反序列化是主要开销 | JPEG、关节原样转发 CDR，不解码；只有 H.264 换外壳要解一次 |
| 安全 | 默认可写，要收窄 `capabilities` | 只开我们注册的通道，`capabilities` 自己给 |
| 和 Lichtblick 的兼容 | 内核同是 SDK，风险相同 | 同左 |

**推荐 (ii)**。地图 D6 原写"只发 `/viz/*`"的意思不变：通道名用 `/viz/*`，只是不再经过 ROS 话题这一跳。

## C. 不连机器人的离线验证

- 可以做。SDK 官方示例 `ws-stream-mcap`：用 `mcap` 读文件，每个通道建 `Channel(topic, message_encoding=…, schema=Schema(name, encoding, data))`，按原时间 `log` 原始字节。来源：https://github.com/foxglove/foxglove-sdk/tree/sdk/v0.30.3/python/foxglove-sdk-examples/ws-stream-mcap
- ROS 2 MCAP 里的 cdr + ros2msg，Lichtblick 能直接解码（A10），所以 JPEG 和 JointState 原样转发就行。
- H.264 那一路先用 `mcap-ros2-support`（不依赖 ROS）解出 CDR，再按 CompressedVideo 发。
- 版本：mcap 1.6.0、mcap-ros2-support 0.6.0 **[已核]**（https://pypi.org/pypi/mcap/json 、https://pypi.org/pypi/mcap-ros2-support/json）。
- 读数据盘上的 MCAP 会更新 atime（M4 记录过）。回放要么拷一小段样本到系统盘，要么沿用 M4 的 bwrap 只读绑定读。

## 未查实

- 机器人上有没有 pip/venv，能不能联网下载 wheel；不能的话从工作站拷 wheel。要等 rollout 结束后只读查看。
- `http://localhost` 页面里的 iframe 连 `ws://<局域网地址>` 时，Chrome 的本地网络访问限制会不会拦。从更私有的回环地址访问局域网地址按规则应当放行，没有实测。离线验证只连 `127.0.0.1`，测不到这一点。
- Ubuntu 26.04 上 Chrome 的 H.264 硬件解码。
- `manylinux_2_28` 的 wheel 为什么比 `2_17` 大很多（19 MB 对 3.8 MB）。
- 静态托管 `.wasm` 时是否需要特定的 MIME 类型。
