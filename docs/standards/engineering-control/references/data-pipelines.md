# 数据与时间语义

用于数据转换、算法和机器人任务。只展开本次需求真正涉及的项目，优先从仓库约定和样本读取，缺少的业务含义再询问用户。

## 契约优先于“能运行”

对关键字段确定：来源、含义、类型、形状、维度顺序、单位、坐标系（如适用）、缺失和无效值行为。state、action、command 等角色不能仅凭字段形状相同互换。

区分完整缺失、局部断档、解码损坏和真实零值。只有配置或已确认契约允许时才填充；记录填充对象、数量和来源，说明是否进入统计和训练。维度数相同仍可能发生维度名称或顺序变化，需要按字段语义决定拒绝、重排或接受。

对浮点阈值检查业务范围和有限性；对维度、计数和长度检查空值、零值及越界。配置合并后的校验应覆盖命令行或环境覆盖路径。

## 时间选择是一项业务规则

写清时间戳来源与单位、时钟关系、参考时间轴、排序和重复值规则。根据数据用途选择 nearest、只取过去、插值或其他策略，并明确：

- 是否允许选到未来样本；并列距离怎么选。
- 最大时间差、复用同一消息是否允许。
- 不满足规则时如何标坏、切段或丢弃。
- 输出时间轴保留原始时间，还是按固定帧率重新编号；这会损失什么信息。

离线转换采用 nearest 不自动构成错误，也不自动适合在线控制或因果训练；结合任务语义判断。改变容差、重采样方法或填充策略属于行为变化，验证必须检查结果质量而不只是通过率。

## 计划是可检查的数据

对对齐、筛选、分段等任务，适合时先生成包含索引、原因及保留区间的结果对象，再由执行和报告使用。输入清洗、可选项判定和最终生效配置也应与这份计划一致。

需要两遍扫描时，明确扫描序号、时间排序位置、输出帧号之间的映射，重复时间戳采用确定的选取规则。对于有前后依赖的格式，输出不使用某条消息不意味着解码器可跳过它。

规划步骤的内存仍需要估计。全量收集时间戳或缓存乱序帧并不会因为“分了两遍”自动获得内存上界；根据预计规模选择窗口、分块或明确容量限制。

## 验证例子从规则反推

| 规则 | 能暴露错误实现的输入 | 需要观察的结果 |
| --- | --- | --- |
| 距离相同取较早值 | 参考时间 5，候选 0 与 10 | 选择 0，而不是只检查结果存在 |
| 超过阈值才拒绝 | 距离为阈值、阈值加一个时间单位 | 前者接受、后者拒绝 |
| 最短段长度包含边界 | 长度分别为 N−1 和 N | 丢弃前者、保留后者 |
| optional 只允许整体缺失时填充 | 完全缺失与局部断档分别构造 | 按两种情况各自的契约处理 |
| 帧与记录一一对应 | 小样本每条记录带独立编号 | 回读时检查编号对应，数量相等还不够 |
| 配置覆盖仍需合法 | 文件合法、命令行覆盖为非法值 | 写出之前拒绝并指出生效值来源 |

不要无条件套用表中的业务规则；先确定本任务采用什么规则，再选能区分正确与错误实现的输入。

输出回读按契约检查数量、形状、关键值、索引连续性和跨文件引用。小样本通过说明该样本范围内成立；长时间运行、完整视频链路或下游加载兼容性需要各自的证据。
