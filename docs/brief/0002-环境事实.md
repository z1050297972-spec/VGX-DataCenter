## F1 存储：导航层和数据盘是分开的

- `/mnt/datasets` 位于系统盘 `/dev/nvme0n1p2`（ext4，1.1T，剩约 334G）。里面只有软链接和 JSON，本项目称它为**导航层**。
- 真实数据在两块独立的 ext4 机械盘上（WDC WUH722020，各 18.2T）。没有 RAID、LVM 或存储池，`/etc/fstab` 里都以 `nofail` 挂载：
  - `/mnt/dataset1`（`/dev/sda`）：19T，已用 16T，剩 **1.6T（91%）**
  - `/mnt/dataset2`（`/dev/sdb`）：19T，已用 17T，剩 **937G（95%）**
- 130T NAS 预计一周内接入（见 0001）。
- 来源：`df -h`、`lsblk`、`findmnt /mnt/datasets`

## F2 导航层的结构

- 共有 35 个数据集。每个数据集在两个视图里各有一个**真实目录**（不是指向另一个视图的软链接）：
  - `按任务/<数据集>/`：35 个
  - `按格式/<格式>/[<版本>/]<数据集>/`：
    - `lerobot/3.0/` 下 31 个；`lerobot/2.0/` 和 `lerobot/2.1/` 为空
    - `mcap/` 下 2 个：EgoProStandard、R1_lite_table_withdrawing_mcap
    - `tar、tar.gz（含分卷）/` 下 2 个：agibot_world_2026、agibot_world_alpha
- 每个目录里有：
  - 一个或多个软链接，常见形态有三种：
    - 单个 `原始数据 -> /mnt/datasetN/...`
    - 跨两块盘时用 `原始数据__dataset1`、`原始数据__dataset2`，例如 EgoProStandard
    - 按子目录逐个链接，例如 agibot_world_alpha 的 `observations/parameters/proprio_stats/task_info`，agibot_world_2026 的 `ImitationLearning/ReinforcementLearning/RichInteraction/simulation`
  - 三个 JSON：`原始路径.json`、`数据集信息.json`、`子任务.json`
- 两个视图合计 70 份 `原始路径.json`。2026-10-20 检查时没有断链（`find 按任务 按格式 -xtype l` 无输出）。
- `索引/` 为空。`解压样本/` 有两个智元样本，其中一个目录名有拼写错误：`agitbot_world_2026_richinteraction_4439_458713`。
- 来源：`ls -la /mnt/datasets/按任务/*`、`find /mnt/datasets/按格式 -maxdepth 3`

## F3 `原始路径.json` 就是软链接清单

以 `按任务/libero_10/原始路径.json` 为例：

```json
{
  "schema_version": 1,
  "dataset_id": "dataset-14",
  "dataset_name": "libero_10",
  "dataset_roots": ["/mnt/dataset1/libero_v3/libero_10"],
  "view": "task", "format": null, "version": null,
  "links": [{"name": "原始数据", "source_path": "/mnt/dataset1/libero_v3/libero_10",
             "entry_path": "按任务/libero_10/原始数据", "source_type": "directory"}],
  "sources": [{"source_id": "src_0b33c900c7fa", "original_path": "...", "direct_path": "...",
               "format": "lerobot", "version": "3.0", "entry_path": "...",
               "source_role": "data", "validation_status": "metadata_and_references_pass"}],
  "notes": [],
  "source_files_modified": false
}
```

- 结论：`links[]` 就是软链接的登记表。任何建链或改链操作都必须同步写回这份文件。

## F4 两个视图中的副本靠 `dataset_id` 关联

- 同一个数据集在两个视图里的 `数据集信息.json` 完全相同。
- 两份 `原始路径.json` 只有这些字段不同：`view`（task/format）、`format`、`version`、`entry_path`。
- 来源：`diff 按任务/libero_10/原始路径.json 按格式/lerobot/3.0/libero_10/原始路径.json`

## F5 另外两个 JSON 的形态

- **`数据集信息.json`**：
  - 顶层字段：`dataset_id`、`title`、`fields[14]`、`summary_path`、`summary_sha256`、`summary_anchor`、`snapshot_date`、`extracted_at`。
  - `fields[]` 每项是 `{number, name, value_markdown}`，值是 **Markdown 文本**，不是结构化字段。
  - 14 项依次是：数据集标识、地址、类型与组成、数据大小、采集机器人型号、任务与场景、数据格式、FPS、相机配置、状态维度、动作维度、动作控制方式及单位、轨迹／帧数、信息来源与核验日期。
- **失效引用**：`summary_path` 指向 `/mnt/datasets/文档/两块数据盘数据集信息汇总_14项标准_2026-10-12.md`，`文档/` 下已经没有这个文件。`文档/` 里的文档还引用了不存在的 `/mnt/datasets/预览/`。
- **`子任务.json`**：`schema_version: 1`，包含 `tasks[]` 和 `semantics`。体积差别很大，最大的是 `按任务/agibot_world_2026/子任务.json`，约 14MB。
- 来源：`cat 按任务/libero_10/数据集信息.json`、`ls -la 按任务/agibot_world_2026`

## F6 `按格式` 的目录深度不统一

- `lerobot/` 下面还有一层版本目录（2.0/2.1/3.0）；`mcap/` 和 `tar、tar.gz（含分卷）/` 下面直接就是数据集，没有版本层。
- 目录名里有中文标点（`、`、`（）`），URL 和命令行参数都要正确编码或转义。

## F8 两台机器人与现有工具

- **Galaxea R1 Lite**：
  - ROS 2，录制格式是 MCAP，关节话题是标准 `sensor_msgs/JointState`。
  - 反馈话题 `/hdas/feedback_arm_{left,right}`、`/hdas/feedback_gripper_{left,right}`；目标话题 `/motion_target/target_joint_state_arm_{left,right}`、`/motion_target/target_position_gripper_{left,right}`。
  - 相机：head_left（作同步参考）、wrist_left、wrist_right。
  - 来源：`/mnt/datasets/工具/mcap2lerobot/configs/r1lite.toml`
- **AutoLife（云蝶）**，由 CB_Autolife_Data_Collector 采集：
  - ROS 2 Jazzy + CycloneDDS。
  - 关节状态是 `std_msgs/String` 里的 JSON，话题为 `/topic_arm_whole_body_and_gripper_current_joints_status_*`；默认 16 维（两条 7 自由度机械臂 + 两个夹爪）。
  - 相机默认读共享内存 `/dev/shm/camera_image_buffer_<名>`。
  - 控制协议：命名管道接收 `start/save/discard/mark_subtask/quit`，结果写进带 request ID 的状态 JSON；也支持 SIGUSR1（保存）和 SIGUSR2（丢弃）信号。
  - 边录边写 LeRobot，依赖 lerobot ≥ 0.6，推断为 v3.0 格式，**没有用样本输出确认过**。
  - **没有实时画面，也没有关节曲线。**
  - 来源：GitHub 仓库的 README、`record_lerobot_official.py`、`start_lerobot_official_collect.sh`
- **mcap2lerobot**（Rust，edition 2024）：
  - 子命令 `info`、`verify`、`convert`，可输出 LeRobot v3.0 或 v2.1。
  - 模块分层清楚，没有循环依赖。
  - 错误处理：anyhow，在拥有身份信息的那一层补充上下文；验证和转换共用同一条同步规则；用 indicatif 显示多进度条。
  - 有 21 个单元测试，没有集成测试。
  - 成文的工程规范在 `docs/skills/engineering-control/`，已原样复制到本仓库的 `docs/standards/engineering-control/`。
  - 来源：`/mnt/datasets/工具/mcap2lerobot/src/`
