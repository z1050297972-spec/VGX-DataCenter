# 血缘写在导航层，转换产物经暂存区检查后入库

Status: accepted（2026-10-22，决策票「工具清单与转换血缘」）

现在导航层里的 `R1_lite_table_withdrawing_lerobot`，几乎可以肯定是用 mcap2lerobot 从 `R1_lite_table_withdrawing_mcap` 转出来的，但哪个版本、哪份配置、哪几天的输入，哪里都没有记。工具目录里还有没提交的配置改动，这时转出来的东西事后无法复现。所以我们规定：数据集"是怎么来的"写在导航层，和数据集放在一起；工具按 git 提交定版本；转换产物先进暂存区，检查通过才入库。

## 具体做法

- **工具库**：就是导航层里的 `工具/`（非数据集目录，平台不扫描、不写），位置写在平台配置里。每个工具一个子目录，自己是一个 git 仓库，根目录有一份 `tool.toml` 清单，清单是事实来源，数据库只放索引。
- **工具的版本**：以 git 提交为准。工具目录有没提交的改动，平台拒绝启动作业。平台不负责构建工具。
- **调用**：参数列表启动子进程，不经过 shell。运行环境只有两种：二进制，或 conda 环境里的 Python（直接调用环境里的解释器）。改不了的第三方脚本配包装脚本，作为单独的工具登记。
- **血缘**：按任务入口下新增 `来源.json`，现有三个 JSON 的格式不变。里面有数据来源、所属采集任务，以及血缘记录。每条记录写输入的 `dataset_id`/`source_id`、工具名称和提交号、配置文件全文和 sha256、RobotProfile 版本、命令参数、作业编号、起止时间、产物的 `codebase_version`。由 worker 写；记录只追加。
- **暂存区**：工具的输出一律写到平台区的 `暂存/<作业编号>/`。入库检查按产物的格式定（不按工具），分结构、计数、视频、内容四层：通过就自动入库；有警告由人确认；不通过的留在暂存区。入库就是在同一文件系统上改名，再建导航层的入口。失败和中断的目录保留 7 天。
- **转换产物是新数据集**，数据来源沿用输入数据集的。

## Considered Options

- **血缘存在数据库**：放弃。数据库只放能重建的东西（ADR 0006），血缘丢了无法重建。数据库里只放它的索引。
- **配置文件只记路径和哈希**：放弃。配置文件以后会改，作业日志 30 天就删，只有保存全文才能复现。
- **工具放进平台仓库，或者单独放一个目录**：放弃。工具有自己的发布节奏；负责人希望工具和数据集放在一起统一管理，而 `工具/` 本来就是非数据集目录。
- **统一用 AV1 编码**：放弃。两张 RTX 3090 编不了 AV1，现有的 R1 Lite 数据和智元样本都是 HEVC。编码只作为每个数据集的事实记录下来，HEVC 和 AV1 可以并存。

## Consequences

- 现有 35 个数据集没有 `来源.json`。缺这个文件时，按"数据来源未知、来历未知"处理，一致性面板只给提示。由人在网页上标注，每次标注是一个写导航层的小作业。
- 建入口、改指向这些写导航层的规则，要把 `来源.json` 算进去（「软链接接口规则」）。
- mcap2lerobot 现在没提交的配置改动，要先提交才能接入。上报协议在 M4 接入。
- 下载的 v3.0 数据导出成 v2.1，需要另写一个工具，M4 再做。

## 修订（2026-11-06，M1.5 第 15 张：数据来源挪出来源.json）

负责人："保留来源.json，只存血缘"。本节补充本 ADR，原文不改；和原文不一致的地方以本节为准。

- **数据来源改放 `数据集信息.json` 顶层的 `data_origin`**，和场景、任务、型号一样是人工标注字段，走普通字段编辑；不再记 `data_origin_set_by`，谁改的靠操作日志和变更记录（ADR 0009）追溯。
- **`来源.json` 升到第 2 版**：只存 `dataset_id`、`dataset_name`、`collection_task_id` 和血缘记录。第 1 版照旧能读，其中的数据来源字段忽略；平台写出的一律是第 2 版。血缘记录只追加的规则不变。
- 现有 35 份的 `data_origin` 由一次回填作业复制到 `数据集信息.json`，同一作业把 `来源.json` 改写成第 2 版，可以撤回。

## 修订（2026-11-08，M3：人工登记转换关系）

负责人选"要，写进来源.json"；M3 决定"采集任务就是数据集"。

- **人工血缘记录**：用户可以在数据集详情里登记"由哪些数据集转换"，写成 `来源.json` 血缘里的一条现有格式记录：`kind` 为"转换"、`status` 为"来历部分未知"、`recorded_by.kind` 为"人工补录"，`inputs` 只填 `dataset_id`（不带 `source_id`）。人工补录的记录可以删除（登记错了要能改，负责人"所有的内容都是用户可编辑的"）；工具和下载写的记录仍然只追加。
- **`collection_task_id` 不再使用**：采集任务就是数据集本身，不需要再指向别处。读时忽略，写时保持原样。
- 转换作业自动写血缘留到 M4。
