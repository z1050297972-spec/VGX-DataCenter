# 技术栈：Python 3.12 模块化单体 + 同步 SQLAlchemy + React 单页应用

Status: accepted（2026-10-21，决策票「技术栈与工程规范」）

平台是一个 Python 3.12 包 `rdp`（`src/rdp/`），用 uv 管理环境和锁文件，原生运行，不进 Docker。Web 服务用 uvicorn，配置文件用 TOML。数据库用 SQLite（WAL）+ SQLAlchemy 2 + Alembic，**只用同步写法**。前端（`src/web/`，见 ADR 0001）用 pnpm、TanStack Router、TanStack Query、Ant Design，前端类型用 openapi-typescript 从 OpenAPI 生成，请求用 openapi-fetch 发。运维命令用标准库 argparse；口令哈希用 argon2-cffi；登录会话自己实现，存在数据库里。类型检查用 basedpyright 严格模式。平台运行时不依赖 lerobot，见 ADR 0003。

选这一组的原因：平台只有一个人维护，代码全部由 AI 编写，所以优先选依赖少、写错了能被类型检查当场拦下的方案。平台几乎每个功能都要碰宿主机（挂载、软链接、网卡、SSH 密钥），所以原生运行。

## Considered Options

- **async SQLAlchemy**：放弃。平台并发很低（几个人用，作业另有 worker 进程），而 async 会让整条调用链都变成 async，还要多一个 aiosqlite 依赖。FastAPI 的同步路由跑在线程池里，够用。
- **PostgreSQL**：放弃。数据集的事实来源是导航层，数据库只存索引、登记信息和日志，数据量小，SQLite 足够，还省掉一个要运维的服务。
- **React Router**：放弃，选 TanStack Router。TanStack Router 对路由和 URL 查询参数（页签、筛选条件）都做类型检查，写错了 tsc 直接报错。React Router 的资料更多，但 v6 和 v7 的写法混在一起，AI 容易混用。
- **Mantine、shadcn/ui**：放弃，选 Ant Design。数据管理后台要用的树、表格、表单、描述列表，Ant Design 都现成，还自带中文。shadcn/ui 要把组件源码拷进仓库，维护面更大。
- **JWT 这类无状态令牌**：放弃。「交互形态与前端路线」定了"账号停用或删除时，已登录的会话立刻失效"，只有服务端会话能做到。会话表存随机令牌的哈希，浏览器端用 HttpOnly、SameSite=Lax 的 cookie。
- **passlib，或者用 `hashlib.scrypt` 自己拼**：放弃。passlib 已经停止维护；自己拼会多写安全相关的代码。
- **Typer**：放弃。不做面向用户的命令行（ADR 0001），运维命令只有四五个，用 argparse 就够了。
- **PyPI 上的 pyright**：放弃，改用 basedpyright。前者第一次运行要联网下载，在 Codex 的沙箱里跑不起来（0006）。
- **pre-commit 框架**：放弃。它第一次运行要联网下载各个钩子的环境。改用普通的 git 钩子 `.githooks/pre-commit`，直接跑 `make check`。

## Consequences

- Python 3.12 的安全支持到 2028-10 结束，到时候要升级。用 uv 升级时，改一行版本号、重跑一遍检查就行。
- Node 22 在 2027-04 停止维护。Node 只用于前端构建和检查，不承担线上服务，到时候再升级。
- basedpyright 能不能在 Codex 沙箱里运行，要在 M0 第一张工单里实测。如果不行，退回用 npm 安装 pyright；再不行，就只在评审时由 Claude 运行类型检查。
