# 本地备份与恢复：每天全量备份数据库和导航层，停服后恢复

Status: proposed（2026-11-01 执行线起草，**还没实施，负责人也还没确认**。负责人说先留着；决策票「备份方案」的本地部分，NAS 部分等「NAS 接入事实」关掉后补）

账号、两种日志、作业记录只存在于数据库里；导航层是数据集唯一的事实来源（ADR 0006）。这两样现在都只放在系统盘上，而且没有备份。NAS 还没接入，所以先做本地备份：worker 每天把数据库和导航层各做一份全量备份，放到平台状态目录下的备份目录里；出事以后，停掉服务，用运维命令从某一份备份恢复。备份目录的位置可以配置，等 NAS 接入以后，指到 NAS 平台区下就是异地备份，到时另开一张票处理"NAS 不在线时怎么办"。

## 具体做法

### 备份什么

- **数据库**：用 SQLite 的在线备份 API 拷出一份一致的副本，不直接 `cp` 运行中的库文件。
- **导航层**：用 tar.gz 打包，**软链接只保存链接本身**，不跟进去复制数据。
  - 默认排除顶层的 `解压样本/`、`工具/`、`VGX_video/`，排除名单写进配置，可以改。
  - 实测按任务、按格式两个视图合计约 38 MB，214 个文件，84 条链接，每天全量打包的开销可以忽略。
- **不备份**：
  - 数据集索引：能从导航层重新扫出来；
  - 运行日志和作业日志：保留期本来就只有 30 天，作业记录随数据库备份。

### 一份备份长什么样

- 一份备份是一个目录：`<备份目录>/<UTC 时间，如 20261101T020000Z>/`，里面三个文件：
  - `rdp.sqlite3`：数据库副本；
  - `nav.tar.gz`：导航层；
  - `manifest.json`：平台版本、数据库版本、导航层根路径、排除名单、各文件的 sha256 和大小，以及数据集数、链接数、文件数。
- **先写临时目录，全部写完、校验通过，再改名成正式名字**。没有 `manifest.json` 的目录一律当成不完整的备份，不参与恢复，也不计入保留。
- 文件权限 0600，目录 0700，和数据库文件一致（M0 第 13 张）。

### 什么时候备份

- **定时**：worker 每天到点（默认本地时间 03:00，可配置）提交一次备份作业，提交人记为"系统"。
- **手动**：管理员可以在作业页面提交，运维可以用命令 `rdp backup`。命令在 worker 停着的时候也能用。
- **迁移前**：`rdp migrate` 已有的迁移前数据库备份（M0 第 5 张）保持不变，和这里的备份分开存放、分开清理。
- **导航层写锁**：备份作业在打包导航层期间持有导航层写锁，免得打进去一个写了一半的状态（和重新扫描的做法一致）。持锁的时间就是打包 38 MB 的时间，秒级。

### 保留多久

- 保留最近 7 份日备份，再加最近 4 周里每周最早的一份。总保留期不超过 30 天，不会超过日志的保留期。
- 每次备份成功后清理一次，只删本平台命名格式的目录，不认识的东西一律不碰。

### 怎么恢复

- 运维命令 `rdp restore <备份名> [--db] [--nav]`，两个开关都不给时两样都恢复。
- **必须先停掉 Web 和 worker**：命令检查 worker 锁和 Web 端口，有一个还在跑就拒绝。
- **恢复前先自动备份一次当前状态**，所以恢复本身也能撤回。
- **先校验**：`manifest.json` 里的 sha256 全部对上才开始恢复。备份的数据库版本比当前代码新，就拒绝；比当前代码旧，恢复后提示运行 `rdp migrate`。
- **恢复数据库**：先写到状态目录下的临时文件，再原子改名替换，同时删掉旧的 -wal、-shm。
- **恢复导航层**：只动备份里有的顶层目录，排除名单里的目录不碰。
  1. 解压到导航层根下的隐藏临时目录 `.rdp-restore-<时间>/`，和导航层在同一个文件系统上，改名才是原子的；
  2. 对每个顶层目录，先把现有的改名挪进临时目录，再把解压出来的改名挪到原位；
  3. 任何一步失败，就按相反顺序挪回去，把导航层恢复原样；
  4. 全部成功以后，删掉临时目录。
- 恢复以后，worker 启动时会自动全量重新扫描，索引随之重建。

### 和"撤回"的分工

- 误改了几处、知道是哪个作业改的：用作业的"撤回"（ADR 0009），粒度到单个作业，不用停服。
- 误改了一大批、或者导航层坏了说不清楚：用 `rdp restore --nav` 退回某一天，要停服。
- 系统盘损坏：在新盘上装好平台，把备份目录拷过来，再 `rdp restore`。备份目录还在同一块系统盘上的时候，这条路走不通，这正是要尽快接 NAS 的原因。

## 后果

- 系统盘损坏仍然会连备份一起丢，直到备份目录指到 NAS 或别的盘。在那之前，运维手册要提醒：定期把备份目录拷到别处。
- 每天多一个几秒的作业，备份目录总共占约 30 份 × 几十 MB。
- 恢复要停服，是有意的：恢复期间不能有人写导航层，也不能有人写数据库。
