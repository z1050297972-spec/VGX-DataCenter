# 只做 Web：React 单页应用，由 FastAPI 同进程托管

Status: accepted（2026-10-21，决策票「交互形态与前端路线」）

平台只提供 Web 界面，不做面向用户的 CLI。前端是 Vite + React + TypeScript 的单页应用；FastAPI 只提供 `/api/*` 下的 JSON 接口，并在同一个进程里托管前端的构建产物。服务监听 `0.0.0.0`，局域网和 tailnet 里的多人用各自的账号登录使用；M0–M4 只走 HTTP。

选这条路的原因：数据集浏览、实时预览（Lichtblick 用 iframe 嵌入）、录制按钮都是图形交互；平台只有一个人维护，只守一个入口最省力；React 是负责人指定的；同进程托管让部署只有一个服务、一个端口。

## Considered Options

- **CLI + Web 双入口**（0003 第四、六节，CLI 用 Typer + Rich）：放弃。两个入口要维护两套交互。只保留一个最小的运维命令入口：启动 Web 和 worker、数据库迁移、重建索引、创建首个管理员，不放任何业务功能。"核心函数不依赖入口"的原则保留：领域模块不 import FastAPI。
- **只监听 `127.0.0.1`，从其他机器用远程桌面访问**：放弃。负责人要从其他机器直接打开平台。
- **全站共用一个口令，或者不设鉴权**：放弃。改为多人账号（管理员、成员两种角色），并记录操作日志和登录日志。
- **WebSocket 或 SSE 推送**：放弃。平台自身的实时数据（作业进度、网速、资源占用）都是每秒一次的量级，轮询足够。机器人的实时画面和曲线由 Lichtblick 直连机器人上的 foxglove_bridge，不经过平台后端。将来某一路需要亚秒级推送时，只把这一路改成 SSE。
- **现在就上 HTTPS**：推迟到 M5 开图时再定。

## Consequences

- 其他机器通过 `http://<工作站IP>` 打开平台时，浏览器不把页面当作安全来源，Lichtblick 解不了 R1 Lite 头部相机的 H.264。M5 开图时必须解决 HTTPS。在那之前，前端地址一律写相对路径，不写死 `http://`。
- 登录口令在局域网 Wi-Fi 上是明文传输的（tailnet 内有 WireGuard 加密），v1 接受这个风险。
- 操作日志和登录日志只保留 30 天（管理员可调），到期自动清除，所以超过一个月的操作查不到是谁做的。
- 日志和作业记录同时存账号的内部编号和当时的名字，所以管理员随时可以删除账号，删除后记录显示为"张三（已删除）"。
- 前端源码放在 `src/web/`，所以"Codex 只改 `src/`、`tests/`"的规则不用改。前端依赖和后端依赖一样，都要负责人批准。
- 前端的类型由 FastAPI 的 OpenAPI 生成，`make check` 检查生成的类型有没有过期。
- 端口避开 80、8080、8088，这几个已被本机现有的 Docker 服务占用。
