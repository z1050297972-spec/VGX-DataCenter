# 领域文档

各 engineering skill 在探索代码库时如何使用本仓库的领域文档。本仓库是单上下文布局。

## 探索前先读

- 仓库根目录的 **`GLOSSARY.md`**
- **`docs/adr/`**：读与你将要动的区域相关的 ADR

这些文件还不存在时直接继续：`/domain-modeling`（经由 `/grill-with-docs`、`/improve-codebase-architecture` 调用）会在术语或决策真正定下来时再创建它们。

## 使用术语表的词汇

输出中提到领域概念时（工单标题、重构提案、假设、测试名），使用 `GLOSSARY.md` 中定义的术语；术语表列出的弃用说法一律换成正式术语。

需要的概念还不在术语表里，是一个信号：要么你在发明项目里不用的说法（重新考虑），要么确实有缺口（记下来交给 `/domain-modeling`）。

## 标出与 ADR 的冲突

输出与现有 ADR 矛盾时，明确指出来，再说明理由：

> _与 ADR-0007（……）矛盾，但值得重新讨论，因为……_
