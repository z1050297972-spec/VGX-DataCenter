# 导航层手册

> 读者：在终端里查看或修改 `/mnt/datasets` 的人，以及开发平台的人。
> 依据：ADR 0006、ADR 0009，以及决策票「数据集板块的数据契约」「软链接接口规则」（1A）的 Answer。术语见 `GLOSSARY.md`。
> 状态：初版（2026-10-22）；2026-10-29 按「软链接接口规则」的 1A 补上平台的写入规则（第 9 节）和 `已移除/`。依赖 NAS 的部分（批量迁到 NAS、平台区目录）等它的 1B。

## 1. 导航层长什么样

导航层是数据集的唯一事实来源。它本身只放目录、软链接和 JSON，真实数据放在存储根上。

```
/mnt/datasets/
├── 按任务/                              ← 按任务视图
│   └── libero_10/                       ← 入口：代表完整的数据集
│       ├── 原始数据 -> /mnt/dataset1/libero_v3/libero_10    ← 链接
│       ├── 原始路径.json                ← 这三份是规范副本
│       ├── 数据集信息.json
│       └── 子任务.json
├── 按格式/                              ← 按格式视图
│   ├── lerobot/3.0/libero_10/           ← 同一个数据集在 lerobot 3.0 下的入口
│   ├── mcap/R1_lite_table_withdrawing_mcap/
│   └── tar、tar.gz（含分卷）/agibot_world_alpha/
├── 索引/  文档/  工具/  解压样本/  已移除/   ← 非数据集目录，平台不扫描
```

- **非数据集目录**：平台不扫描，也不当作数据集。登记表是 `索引/`、`文档/`、`工具/`、`解压样本/`、`已移除/` 五项，顶层出现登记表以外的目录或文件，一致性面板会报出来。
  - `工具/` 就是工具库，每个工具一个子目录，自己是一个 git 仓库，根目录有一份 `tool.toml`（ADR 0008）。平台只读不写。
  - `已移除/` 放被移除的数据集的入口，见 9.3。平台不扫描它，只在分配新编号时看它下面的目录名；移除和挪回时由平台写。
- **第四个文件**：`来源.json` 只放在按任务入口，第 2 版只记数据集身份、所属采集任务和血缘（ADR 0008）。数据来源分类另存于 `数据集信息.json` 顶层。缺少来源文件表示“来历未知”。

- **按任务视图**：每个数据集恰好有一个入口，代表完整的数据集。名字叫"按任务"，实际是一个数据集一个目录，不按子任务划分。
- **按格式视图**：入口的路径是 `按格式/<格式目录>/[<格式版本>/]<数据集名>/`，代表数据集在这种格式下可以直接使用的那一部分。一个数据集在这里可以有零个、一个或多个入口。例如 EgoProDemo 在 `lerobot/3.0` 下的入口，只链接到它的 `EgoProStandard-body/lerobot` 子目录。
- **规范副本**：按任务入口里的三份 JSON 就是规范副本。各入口的内容不一致时，以规范副本为准。
- **格式目录登记表**：`按格式/` 下的第一层目录，对应到哪个格式、有没有版本层，以下面这张表为准。出现表里没有的目录时，一致性面板会报出来。

  | 目录 | 格式（`format`） | 有没有版本层 |
  |---|---|---|
  | `lerobot` | `lerobot` | 有，例如 `3.0` |
  | `mcap` | `mcap` | 没有 |
  | `tar、tar.gz（含分卷）` | `archives` | 没有 |

## 2. `原始路径.json`

这份文件装着两份清单：

- **`links[]`** 是这个入口目录里**有哪几条软链接**。每一项对应磁盘上的一条软链接。
- **`sources[]`** 是这个数据集里**有哪些数据块**。一个数据块可以是一个 LeRobot 目录、一个 mcap 文件、一个压缩包，或者一个下载控制文件，各自带有格式和核验状态。

两份清单的条数可以差很多。libero_10 是 1 条链接、1 个数据块；EgoProDemo 是 1 条链接、234 个数据块；agibot_world_alpha 是 4 条链接、215 个数据块。

下面三张表的最后一列"平台怎么用"有四种取值：

- **依赖**：平台读它来做判断，写入时也会改写它。
- **推导**：平台按入口的位置自己算，文件里存的值只用来核对。
- **展示**：原样显示给人看。
- **不改**：保持原值。

**顶层字段**（例子取自 libero_10 在按格式视图里的那份）：

| 字段 | 含义 | 例子 | 平台怎么用 |
|---|---|---|---|
| `schema_version` | 这份文件的格式版本号 | `1` | 依赖：遇到不认识的版本就不解析 |
| `dataset_id` | 数据集的永久编号，两个视图、三份 JSON 里都相同 | `"dataset-14"` | 依赖：用作主键 |
| `dataset_name` | 数据集名，等于入口的目录名 | `"libero_10"` | 依赖：用来核对目录名 |
| `dataset_roots` | 数据集在存储根上的根目录，跨盘时有多项 | `["/mnt/dataset1/libero_v3/libero_10"]` | 依赖：判断数据集在哪个存储根上，核对链接目标 |
| `view`、`format`、`version` | 入口所在的视图、格式和格式版本；在按任务视图里，`format` 和 `version` 是 `null` | `"format"`、`"lerobot"`、`"3.0"` | 推导 |
| `links[]` | 链接清单，见下 | | 依赖 |
| `sources[]` | 数据块清单，见下 | | 依赖 |
| `notes` | 备注 | `[]` | 展示 |
| `source_files_modified` | 建导航层时是否改过数据 | `false` | 展示 |
| `excluded_from_navigation`（只有智元有） | 有意不放进导航层的目录 | `["/mnt/dataset2/agibot_world_alpha/lerobot_v2_output"]` | 展示；一致性面板检查它们还在不在 |
| `navigation_scope`、`task_metadata`（只有智元有） | 说明性的字段 | `"original_component_or_category_directories"` | 展示 |

**`links[]` 的每一项**：

| 字段 | 含义 | 例子 | 平台怎么用 |
|---|---|---|---|
| `name` | 链接的文件名 | `"原始数据"`；跨盘时是 `"原始数据__dataset1"`；智元是 `"observations"` | 依赖 |
| `source_path` | 链接指向哪里（绝对路径）。名字里的 source 和 `sources[]` 无关 | `"/mnt/dataset1/libero_v3/libero_10"` | 依赖：和磁盘上 `readlink` 的结果核对；改指向时改写 |
| `entry_path` | 链接自己在导航层里的位置，相对于 `/mnt/datasets` | `"按格式/lerobot/3.0/libero_10/原始数据"` | 推导：等于入口目录加上 `name` |
| `source_type` | 链接目标的类型 | `"directory"` | 依赖：和目标的实际类型核对 |

**`sources[]` 的每一项**：

| 字段 | 含义 | 例子 | 平台怎么用 |
|---|---|---|---|
| `source_id` | 数据块的永久编号，在两个视图里相同 | `"src_0b33c900c7fa"` | 依赖：两个视图按它配对。不重算，改指向时也不变。平台新登记的数据块，照现有规则（`src_` 加 `sha256(original_path)` 的前 12 位）算一次，之后同样不重算 |
| `original_path` | 首次登记时的位置。`source_id` 就是用它算出来的 | `"/mnt/dataset1/libero_v3/libero_10"` | 不改：改指向时保持原值，一致性面板不检查它 |
| `direct_path` | 现在的位置 | 迁移之前和 `original_path` 相同 | 依赖：一致性面板检查它是否存在；改指向时改写 |
| `entry_path` | 从导航层走到它的路径。链接够不着的，写成绝对路径 | `"按格式/lerobot/3.0/libero_10/原始数据"` | 推导：等于所在链接的 `entry_path` 加上 `direct_path` 去掉链接目标前缀后剩下的部分 |
| `format`、`version` | 数据块本身的格式和格式版本 | `"lerobot"`、`"3.0"`；mcap 的 `version` 是 `null` | 展示；和 `meta/info.json` 里的 `codebase_version` 核对 |
| `source_role` | 数据块的角色 | `data`（数据本体）、`archive`（压缩包）、`archive_collection`（装压缩包的目录）、`download_control`（下载控制文件） | 展示 |
| `validation_status` | 写导航层时（10-16）核验到了什么程度 | 见第 5 节 | 展示，配中文标签 |
| `entry_type`（只有智元有） | `entry_path` 是怎么得来的 | `through_direct_dataset_symlink`（穿过链接）、`original_source_path`（没有链接，写原路径） | 展示 |

## 3. `数据集信息.json`

这份文件保存 14 项文字说明；历史内容来自 10-12 整理的快照，新建数据集可以填写第 4 项以外的文字，后续也可在编辑器补充。第 4 项由平台完整统计后自动写入，不接受手填。两个视图里的这份文件应当完全相同。

| 字段 | 例子（libero_10） | 平台怎么用 |
|---|---|---|
| `dataset_id` | `"dataset-14"` | 依赖 |
| `title` | `"14. libero_10"` | 展示 |
| `subtask_notes` | `"抓取杯子\n放到桌上"` | “子任务”多行纯文本记事本；标量字符串，缺失等同空串，不为旧文件补写；编辑和格式副本同步沿用字段编辑流程，不参与任务筛选或搜索 |
| `fields[]` | 14 项，每项是 `{number, name, value_markdown}`，例如 `{"number": 5, "name": "采集机器人型号", "value_markdown": "本地 robot_type=\`franka\`"}` | 依赖它的结构（编号和名称）；第 4 项自动写入大小、口径和本地统计日期，仅解析约定字节段判定是否更新；其余内容按 Markdown 渲染，不解析 |
| `summary_path`、`summary_sha256`、`summary_anchor` | 指向原始的汇总文档，文档已经不在了 | 展示；一致性面板报"失效引用"（提示） |
| `snapshot_date`、`extracted_at` | `"2026-10-12"`、`"2026-10-16T07:53:13-06:00"` | 展示 |
| `information_scope` | 说明这 14 项是汇总文档的原文，不是重新统计的 | 展示 |
| （没有 `schema_version`） | | 当作 1 |

14 项依次是：数据集标识、地址、类型与组成、数据大小、采集机器人型号、任务与场景、数据格式、FPS、相机配置、状态维度、动作维度、动作控制方式及单位、轨迹／帧数、信息来源与核验日期。其中第 2 项和第 14 项的正文里带有数据盘上的绝对路径。

### 场景多选（M1.5-12）

`数据集信息.json` 顶层的 `scene` 表示多个场景，例如 `"scene": ["tabletop", "kitchen"]`。读取旧字符串时作为单项数组；缺失、`null`、空串按 `[]` 处理；数组去首尾空格、去空项并去重保序。读取及扫描不改写旧文件，下一次保存字段时才在规范副本与格式副本中写成数组，变化纳入预览、回滚和变更记录。

接口里的场景数据以数组表示，editable-fields 的 `["scene"]` 返回 `multiple: true`，字段编辑及新建只接受数组；空数组表示未标注。查询参数 `scene` 仍是单个选中的场景代码，只要数据集数组包含它就能命中。按场景树在每个场景下展示这个数据集，空数组归入“未标注”；根节点数量和大小不因多个场景重复累计。场景可自定义，继续不产生词表外提示。

数据库迁移 `0017_multi_scene` 将旧 `datasets.scene` 文本转换到 `scene_json` JSON 数组列，空值转空数组，保留其余索引及统计值，不批量修改导航层。已有单场景索引无需重新扫描即可浏览；如果升级前已手工写过场景数组，旧扫描器未收录的场景需要重新扫描恢复。平台保存字段后会在同一作业内更新该数据集索引。

### 筛选字段与来源文件（M1.5-15）

`数据集信息.json` 新增键追加在末尾，按格式入口仍整份复制规范副本：

| 顶层字段 | 读取与保存规则 |
|---|---|
| `robot_model` | 文本，读取和字段编辑保存时去首尾空白；缺失、空串、非文本表示未标注。筛选参数 `robot_model=unlabeled` 匹配未标注 |
| `fps` | 正整数，单位帧/秒；缺失或非法表示未标注。筛选参数 `fps=unknown` 匹配未标注；编辑只接受正整数 |
| `data_origin` | 真机采集、UMI 采集、ego 采集、仿真生成、开源下载、未知之一；缺失为未知。修改者由操作日志和变更记录追溯 |

`来源.json` 第 2 版按顺序写 `schema_version: 2`、`dataset_id`、`dataset_name`、`collection_task_id`、`lineage`，不含 `data_origin`、`data_origin_set_by`。第 1 版照旧可读，但其中两个来源字段忽略，既不显示也不参与筛选。平台构造的新来源文件一律为第 2 版；血缘记录只追加的约束不变，格式入口不复制此文件。

数据库迁移 `0018_information_filters` 新增 `datasets.fps`，将旧来源索引置为未知；迁移不读写导航层。升级后需要重新扫描，才能按信息顶层填充新索引。上线回填由管理员预览、确认执行，只新增缺失的顶层 `fps`、`data_origin`，并将来源文件升版；不改已有型号和 14 项信息。回填完成后的索引更新由该作业负责。日常编辑 FPS 不再解析第 8 项文字。

## 4. `子任务.json`

网页不再提供此文件的查看或编辑入口；文件原样保留，后端接口和编辑规则仍保留。用户维护的“子任务”记事本另存于 `数据集信息.json` 的 `subtask_notes`，不会改写此文件。

- 顶层字段有 `schema_version`、`dataset_id`、`dataset_name`、`view`/`format`/`version`（含义同上）、`task_count`、`data_unit`、`semantics`、`tasks[]`、`shared_source_roots`。
- `tasks[]` 的每一项是一个子任务，带有 `task_key`、`display_name`、`label_status`，以及它用到了哪些数据（`sources[]`，可能精确到 episode）。
- 平台读取仍依赖 `schema_version` 和 `dataset_id`，原后端读取及编辑规则为兼容保留；网页已不再按需打开这份文件。当前用户维护的是独立的 `subtask_notes` 记事本，不是这份 JSON 中的结构化子任务清单。

## 5. 平台怎么读这些文件

- **读的时候宽松**：
  - 缺 `schema_version` 当作 1。
  - 省略 `version` 键，等同于 `null`。
  - 不认识的字段原样保留。
  - 只有遇到不认识的 `schema_version`、文件解析失败、缺少依赖的字段时，这份文件才不解析。数据集照常列出，一致性面板会报出问题。
- **以规范副本为准**：按格式入口里的副本，和规范副本对不上时，页面按规范副本显示。
- **五个筛选**：型号、FPS、数据来源、场景、任务全部读取规范副本 `数据集信息.json` 顶层，经扫描进索引。不解析 14 项 Markdown，不从格式副本补值。LeRobot 的 `meta/info.json` 中 `robot_type`、`fps` 仍进索引，但仅用于原文件参考、比对和一次性回填。
- **大小**：由后台的"统计大小"作业来算，结果带统计时间，不是实时值。
  - 每条链接收集 `direct_path` 等于链接目标或位于其下的数据块，按各块的 `format` 统计表观字节数；嵌套时以最深的块为准。块外文件不计入；链接下没有任何数据块时才按整个目标全部大小计。格式缺失或未知的数据块按全部大小计。
  - LeRobot 仅计相对数据块目录的路径中有 `data` 目录的 `.parquet` 普通文件、有 `videos` 目录的 `.mp4` 普通文件和 `meta` 目录的全部普通文件，层级不限；隐藏目录不计入大小。MCAP、压缩包按全部大小计，包含隐藏目录。
  - 目录自身不计大小；不跟随内部软链接，非 LeRobot 格式计软链接自身长度；每个链接目标内硬链接去重。下载残留计数和样例仍覆盖隐藏目录和块外文件；离线或遍历失败时保留旧值和原统计时间。
  - 没被链接的内容不计入。
  - 详情页仅显示统计值及时间，未统计显示"未统计"；页面大小使用 1000 进制，达到 1 TB 时同时显示 GB/TB（不到 1 GB 的页面数值仍按 B、KB、MB 显示），保留两位小数。
  - 完整统计发布后，对 `number=4`、`name=数据大小` 的 `value_markdown` 自动写入：不到 1 TB 时为 `{GB} GB（{千分位字节数} B；LeRobot 只计 parquet、mp4 和 meta，其他格式计全部文件；统计于 {本地日期 YYYY-MM-DD}）`，达到 1 TB 时才为 `{GB} GB / {TB} TB（{千分位字节数} B；LeRobot 只计 parquet、mp4 和 meta，其他格式计全部文件；统计于 {本地日期 YYYY-MM-DD}）`。GB、TB 均按 1000 进制保留两位小数，按原始字节数判断 1 TB 门槛。不到 1 GB 仍只写 GB，例如 `0.63 GB（631,143,349 B；LeRobot 只计 parquet、mp4 和 meta，其他格式计全部文件；统计于 2026-11-06）`；其他示例为 `119.64 GB（119,642,823,842 B；LeRobot 只计 parquet、mp4 和 meta，其他格式计全部文件；统计于 2026-11-07）`。
  - 只从已有文字的 `（N B；` 片段取字节数，N 可以带千分位；等于本次统计就不写，不更新日期；不同或无法解析才覆盖。日期取与调度相同的本地时区，表示大小最后变化时的统计日期，首次同步为首次写入日期。离线、超时、统计失败或不完整时不写。第 4 项仍不可在编辑器修改，也不产生缺记录警告。
  - 统计作业仍不拿写锁，只发布索引并保存自动计划；每次至多提交一个 `nav_size_sync`，覆盖本次需要更新的数据集。该作业不经人工预览确认，沿用写锁、日志先行和变更记录流水线，操作日志以系统身份标注“平台自动”。只替换规范副本第 4 项字符串的原始区间，其他原始字节和键顺序不变；格式信息文件整份同步规范副本。写锁内发现数据集状态与统计时不同，就跳过该数据集，下次统计再写，不使整批失败。写后照常更新索引并触发统计，大小相同不再产生同步作业。
- **`validation_status` 的中文标签**：

  | 值 | 标签 |
  |---|---|
  | `path_exists_only` | 只核对了路径存在 |
  | `archive_not_opened` | 归档没有打开核对 |
  | `metadata_and_references_pass` | 元数据和引用都核对通过 |
  | `attention_required` | 需要关注 |
  | `download_state_only` | 只有下载控制文件 |

  这是 10-16 写导航层时的核验结果，后来数据有变化，它也不会自动更新。

## 6. 存储根

- **已登记的存储根**：现在有 `/mnt/dataset1` 和 `/mnt/dataset2` 两个，都是只读的。NAS 接入后再登记两个：智元数据迁过去的那部分只读；另外单独划出一个平台区，是可写的，平台的下载、转换、暂存、备份产物都写在这里。
- **登记在哪**：存储根写在平台的配置文件里（名字、路径、挂载源、是否可写），网页上不能改。怎么登记、怎么查离线原因，见运维手册"存储根"一节；所有登录账号都能在"存储根"页面看到当前状态。
- **在线**：路径此刻是挂载点，并且挂的正是登记的那块盘（ext4 按 UUID 核对，NAS 按"服务器:导出路径"核对），挂的是整个文件系统而不是其中一个子目录。离线原因分三种：没挂载、挂错了盘、超时。
  - 没挂上时，`/mnt/dataset1` 只是系统盘上的一个空目录，这时算离线。
  - NAS 挂着但不响应时，靠访问超时来发现，也按离线处理。
- **离线时的表现**：
  - 数据集照常列出，三份 JSON 照常能看。
  - 链接标为"存储根离线"，不算断链。
  - 一致性面板顶部报一条，并跳过这个存储根下面的所有检查。

## 7. 在终端里手工修改

手工修改是允许的，但它不受平台的导航层写锁保护，只能靠一致性面板事后发现。改完之后，可以在一致性面板点"排查"，或者在数据集页面点"重新检查"。平台不再定时扫描。

- **先改规范副本**：先改按任务入口里的那份，再把各个按格式入口里的副本同步改好，否则面板会报"副本不一致"。
- **链接和清单一起改**：动了链接，要同时改 `links[]` 里的 `name`、`source_path`、`entry_path`。
- **数据和清单一起改**：删除或移动了数据盘上的目录，要同时更新 `sources[]`、`dataset_roots` 等引用到它的地方。
- **两个字段保持原值**：`source_id` 和 `original_path` 不要改。
- **只用两种方式维护**：导航层只靠平台的写入功能和手工修改来维护。当初生成这些 JSON 的程序已经停用，不再运行。它要是再跑一次，会覆盖已经做过的修改。

平台的写入规则见第 9 节。平台写入前会核对它预览时看到的状态：预览之后、平台真正写之前你改过的数据集，平台那边以"冲突"失败、一行都不写，不会覆盖你的修改。

## 8. 一致性面板上的问题怎么处理

面板只报告，不会自动修复。同一类问题会合并显示，并列出前几个样例。

| 组 | 问题 | 级别 | 怎么处理 |
|---|---|---|---|
| ① JSON 本身 | 打不开、缺少字段、`schema_version` 不认识；三份 JSON 的 `dataset_id` 不一致，或和目录名对不上；只有按格式入口，没有按任务入口；有没登记的格式目录，或者顶层有没登记的目录；存的 `view`/`format`/`version`、`entry_path` 和按位置推出来的不同 | 需要处理 | 在终端里改正 JSON 或目录，然后重新扫描 |
| ② 两个视图之间 | 按格式入口的副本和规范副本内容不同 | 需要处理 | 按规范副本改正按格式那份 |
| ③ JSON 和磁盘之间 | `links[]` 和磁盘上的链接对不上（多了、少了、指向不同）；断链；链接目标不在已登记的存储根下，或不在 `dataset_roots` 之内；`dataset_roots` 或数据块的 `direct_path` 不存在；数据块登记的格式版本和 `meta/info.json` 不一致 | 需要处理 | 把数据或链接恢复回来，或者更新 JSON |
| ③ JSON 和磁盘之间 | 排除目录、子任务、14 项正文、`summary_path` 里引用的东西已经不存在；根目录下有既没链接、也没登记为排除的内容 | 提示 | 了解即可，需要时再更新 JSON |
| ④ 存储状况 | 存储根离线，或者挂错了盘 | 需要处理 | 检查挂载：NAS 在不在线，盘有没有插对位置 |
| ④ 存储状况 | 有没下载完的文件（`.aria2`、`.incomplete`） | 提示 | 确认下载是否完成，必要时重新下载或清理 |

按 2026-10-22 的数据，第一次扫描预计会报出：

- **需要处理，1 条**：agibot_world_alpha 有 3 个数据块指向的转换副本，在 10-17 被删除了。
- **提示，5 条**：
  - 35 个数据集的 `summary_path` 都指向一份已经不存在的汇总文档。
  - 2 个数据集登记的排除目录已经不存在。
  - 2 个数据集的子任务和 14 项正文里，引用了已删除的路径。
  - 2 个数据集有没下载完的文件：agibot_world_2026 有 1 个，EgoProDemo 有 8 个。
  - agibot_world_alpha 的根目录下有没被链接的内容：两个 `.venv`、`README.md`、`scripts/`。

## 9. 平台怎么写导航层

> 依据：ADR 0005、ADR 0009，决策票「软链接接口规则」Answer 的 1A（L1–L19）。依赖 NAS 的部分（智元迁到 NAS、一次改指向改多大范围、访问 NAS 超时、平台区目录布局）等它的 1B，本节不写。

### 9.1 总的规矩

- **都是作业**：建链、新增数据集、改指向、字段编辑（含数据来源）、回填、场景/任务值删除和大小同步，均由 worker 执行。Web 不写导航层，worker 在导航层写锁下写。
- **人工修改先预览，再确认，再核对**：提交前先看预览，里面列出将写哪些文件、哪些链接，以及 `dataset_roots` 的变化。预览时平台记下受影响数据集的状态：按任务入口和它全部按格式入口里，每份 JSON（含 `来源.json`）的 sha256、入口目录的条目名清单、每条链接的 `readlink`。真正写之前再算一次，对不上就以"冲突"失败，一行都不写，重新预览即可。平台自动的 `nav_size_sync` 不需人工确认，但仍核对状态、持写锁并记录日志，详见第 5 节。
- **先写规范副本，再生成按格式入口**：平台只在按任务入口里改，按格式入口的各份都由规范副本重新生成（9.4）。
- **只写导航层**：平台不改链接目标里的任何东西。链接可以指向只读存储根，只是指过去。
- **写失败、断电都会退回**：写之前平台先记下每处原来的样子，写到一半失败或断电，就退回写之前的样子，不往下补完。见运维手册"导航层写入日志和变更记录"一节。
- **永久保留改动历史**：每次改动另存一份变更记录，操作日志清理不影响它。M1.5 第 18 张已删除用户撤回接口和页面入口，历史记录不再用于生成反向计划。改错后需再次编辑改回，或由管理员利用已有备份处理；写入失败后的自动回滚与恢复仍保留。

### 9.2 建链

1. **校验**（L1，0003 4.4 的五条加 L1 补的四条），全部满足才能提交：
   - 目标存在，并且位于某个已登记的存储根下；目标按 `realpath` 解析之后，也必须落在已登记的存储根下。
   - 目标不在导航层内部，不能链到链接。
   - 目的路径在 `按任务/` 或 `按格式/` 之下。
   - 目的路径已经存在时不覆盖（见下面的"目的路径已存在"）。
   - 链接一律用绝对路径。
   - 不修改目标里的任何东西。
   - 链接名不含 `/`、不以 `.` 开头，不和入口里的四份 JSON（`原始路径.json`、`数据集信息.json`、`子任务.json`、`来源.json`）同名。
   - 目标不在 `dataset_roots` 之内时，预览里明确提示"将把 X 加进 `dataset_roots`"。
2. **目的路径已存在**（L2）：拒绝，提示改走改指向。只有一个例外：已存在的链接正好指向同一目标、并且已经登记在 `links[]` 里，这时按"已经是这样了"成功，什么都不写。
3. **写回 `原始路径.json`**（L3）：
   - `links[]` 追加一项：`name`、`source_path`、`source_type`，`entry_path` 由平台推导。
   - 目标没被现有数据块覆盖时，`sources[]` 追加一个数据块：`original_path` 和 `direct_path` 都等于目标；`source_id` 照现有规则算一次，之后不重算；`format`/`version` 取自预览时读到的 `meta/info.json`；`validation_status` 是 `path_exists_only`。一个链接目标对应一个数据块。
   - 目标不在 `dataset_roots` 之内时，追加进去。
4. **两个视图**（L4）：链接一律建在按任务入口。要不要同时放进按格式入口、放进哪几个（0 到多个），在预览里勾选；勾上的按格式入口由规范副本重新生成。

### 9.3 新增和移除数据集

- **新增**（L5）：一个作业里建好全套：
  - 按任务入口：目录、链接、三份 JSON 的骨架，以及第 2 版 `来源.json`（空血缘）；必填数据来源写入信息顶层，下载入库固定写“开源下载”。
  - 预览里勾选的按格式入口（0 到多个）。
  - 信息内容：`数据集信息.json` 的 14 项按固定顺序写好编号和名称。新建预览可带可选 `information`：`fields` 中每项含 `number` 和 `value_markdown`，可只填部分；编号必须是 1–14 的整数，不得为 4、不得重复。给出的正文按编号写入，未填项和第 4 项保持空串。省略 `information`（或为 `null`）仍生成原有空骨架；`子任务.json` 仍写 `tasks: []`、`task_count: 0`。
  - `information.robot_model` 默认为空串，非空才写入顶层；`information.scene`、`tasks` 是字符串数组，默认为空数组，和第 5、6 项的文字分别保存。场景、任务去首尾空格、去重保序；不接受保留字 `unlabeled` 或空数组项，非法参数在提交预览时返回 422。新建时 `scene` 一律写数组（未填写写 `[]`）；`tasks` 非空才写入。
  - 预览差异以原有空骨架为基线，列出实际计划中的文字和分类值；按格式入口的信息文件沿用规范副本整份同步。下载入库流程本次不变。
- **编号**（L6）：平台在写锁下扫描 `按任务/` 和 `已移除/`，取最大编号加 1，写成 `dataset-36` 这样，至少两位。编号不复用。
- **移除**（L7）：只移除导航层的入口，不删数据。按任务入口和它的各按格式入口，整体挪到 `已移除/<dataset_id>_<名称>/` 下，JSON 原样保留，以后可以挪回来恢复。移除过的编号留在 `已移除/` 的目录名里，所以不会被重新分配。
  - 这个功能放进哪个里程碑还没定（「软链接接口规则」"待落实"第 8 条）。在那之前，`已移除/` 只是登记表里的一个目录名。
  - **不要在终端里删 `已移除/` 下的目录**：编号靠它们保证不复用。

### 9.4 按格式入口怎么由规范副本生成

- **链接**（L8）：以这个按格式入口自己的 `links[]` 为准。
- **`sources[]`**：取规范副本中 `direct_path` 落在本入口某个链接目标之下的数据块，`entry_path` 重新推导。例如 EgoProDemo 的 `lerobot/3.0` 入口只链接 `EgoProStandard-body/lerobot`，它的 `sources[]` 就只收这个子目录下的数据块。
- **`子任务.json`**：只保留引用到入选数据块的任务，任务内部的数据引用也同样筛。
- **`数据集信息.json`**：整份复制。
- **`来源.json`**：只在按任务入口里有，按格式入口不放副本。
- **链接够不着的数据块**（L9）：只留在规范副本里，`entry_path` 保持绝对路径；按格式入口不收录。例如 agibot_world_alpha 有 3 个这样的数据块（10-17 被删掉的转换副本），它的按格式那份现在还收着它们；平台第一次写 alpha 时，按格式那份会少这 3 个，预览里会列出。

### 9.5 写出的格式

- **保持原样**（L11）：保持原来的键顺序，2 空格缩进，中文不转义（`ensure_ascii=False`），文件以换行结尾。新键追加在末尾，不认识的键原样保留。所以预览里的差异只显示真正改了的行。
- **推导字段整组重新生成**（L10）：`view`/`format`/`version` 由入口的位置推出，写的时候整组重写，原来省略的 `version` 会写成 `null`。这是平台第一次写某个数据集时常见的差异，不是改格式。
- **不补 `schema_version`**：`数据集信息.json` 从来没有 `schema_version`，平台写回时也不补。读的时候仍然当作 1（第 5 节）。
- **两个字段不改**：`original_path`、`source_id` 保持原值。

### 9.6 改指向

改指向就是把一个数据集里的某个路径前缀换成新的，例如数据从一块本地盘挪到另一块以后。一次改一个数据集，两个视图一起改。

- **前缀的写法**（L17）：新旧前缀都是不带结尾 `/` 的绝对路径。
- **边界**：前缀后面必须紧跟 `/`，或者到了 JSON 字符串的结尾。所以 `/mnt/dataset1/agibot_world_2026` 不会误伤 `/mnt/dataset1/agibot_world_2026_sim`。在 Markdown 正文里，"结尾"还包括后面跟着空白、`` ` ``、引号、`)`、`]`、`>`，或者中文标点（，。；：）」）。
- **替换范围**（L18）：三种 JSON（`原始路径.json`、`数据集信息.json`、`子任务.json`）里所有字符串值中符合边界的都替换，包括 `direct_path`、链接的 `source_path`、`dataset_roots`、子任务里的路径、14 项 Markdown 里的路径；只有 `original_path` 例外。链接本身也跟着改指向。
  - `来源.json` 不改写，它的血缘记录只追加。
  - 预览按字段分组给出替换数量，Markdown 和 `notes` 里的每一处单独列出。
- **新位置核对**（L19）：
  - 旧位置现在存在的路径，新位置必须全部存在，并且落在已登记、在线的存储根下，缺一个就整批拒绝，一行都不写。
  - 旧位置本来就不存在的（例如 alpha 那 3 条），照样替换，预览里标"旧位置原本就不存在"。
- **按格式入口**：先改规范副本，再按 9.4 重新生成这个数据集的全部按格式入口。

### 9.7 三个典型情况

1. **建链时目的路径已存在**：预览阶段就会报出。已经指向同一目标、并且登记在 `links[]` 里的，作业直接成功、什么都不写；否则请改走改指向。
2. **改指向改到一半时断电**：来电后 worker 先把已经写好的文件退回原样，没写的不动，作业显示"已中断"；退回完成以后，才放行别的写作业。重新预览、再提交即可。如果有文件在这期间被人在终端里改过，既不是原样、也不是平台写的样子，作业会显示"恢复失败"，写作业被挡住，等管理员处理，见运维手册"写导航层的作业恢复失败"。
3. **改指向后发现指错了**：重新提交改指向预览，核对后确认写入。历史变更记录永久保留，可用于核查原来的改动。
