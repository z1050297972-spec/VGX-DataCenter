- 读 MCAP 用普通 `File::open` + mmap，不带 O_NOATIME：直接对数据盘运行会更新 atime，产生写入。

## 决定

### 1. 工具原样不动，平台侧建"登记包"

- 工具留在 `工具/mcap2lerobot`，平台对它只读、只执行。
- 平台仓库新增 `tools/<工具名>/`，每个工具一个登记包，放三样：
  - `tool.toml`：清单（身份、输入输出格式与版本、适用型号 → 配置、运行方式、程序路径与 sha256、是否要 GPU、命令模板、预检命令、上报方式）。字段沿用 `../platform-v1/assets/15-tool-manifest-lineage/tool.toml` 草样，拆票时定稿。
  - `configs/<型号>.toml`：平台自己保存的转换配置。初始内容逐字复制工具里现在的 `configs/r1lite.toml`（dataset-29 就是用这一版转出来的），运行时用 `-c` 指向这份。
  - `adapter.py`：包装脚本，负责启动工具并按 ADR 0004 的协议上报。
- 登记包随平台代码评审、按平台 git 提交管理；以后新增工具就是新增一个登记包（一张小票）。
- "适用型号"的键用和数据集 `robot_model` 同一套字符串，不建型号表（M1.5、M3 的决定）。

### 2. 版本锁定改成核对程序指纹

- 取代"工具目录有未提交改动就拒绝运行"：清单里写程序文件的 sha256，作业启动前核对；对不上就拒绝，诊断提示"工具程序已变化，需要重新登记"。
- 清单另记登记时核对到的源码提交号和"有未提交改动"这一事实，只作说明，不参与运行判断。
- 血缘里记：工具名、版本、提交号说明、程序 sha256、配置全文和 sha256、命令参数、作业编号、起止时间。

### 3. 逐帧进度：包装脚本给工具一个伪终端

负责人要在前端看逐帧进度。工具不能改，就让它以为自己在终端里：

- `adapter.py` 用标准库 `pty` 给工具的 stderr 开伪终端，窗口设宽（200 列，`TIOCSWINSZ`），工具照常画进度条；stdout 走普通管道，两路原始输出仍完整记进作业日志（ADR 0004）。
- 包装脚本读伪终端输出，去掉控制序列，按上面三种行的格式取出：阶段、总百分比、每个特征（相机、state、action）的 已完成帧/总帧、扫描阶段的消息数。换成协议里的"进度"事件，每秒最多 2 条。
- 前端：作业详情显示总进度条，下面每个相机一条"1234/5678 帧"，带速度和剩余时间。网页按 M0–M4 的约 1 秒轮询更新，所以是每秒刷新一次的逐帧计数，不是 30 帧动画。
- 安全边界：
  - 只有进度来自解析。成败只看退出码、`verify` 和入库检查，不看解析结果。
  - 程序指纹锁定，输出格式不会悄悄变；登记包带一份真实运行录下的终端输出作测试样本，重新登记时必须重新过。
  - 解析不出来时退回阶段级进度，记一条警告诊断，不让作业失败。
- 和 ADR 0004 的关系：0004 否决的是"平台解析各工具的 stdout"。这里的解析限定在单个工具的包装脚本里、只取进度、程序版本锁定，要写进 ADR 0004 的修订节。
- 不需要新依赖（`pty`、`fcntl`、`termios`、`re` 都是标准库）。

### 4. 数据盘不写：工具在 bwrap 里运行

- 用 `bwrap` 启动工具：输入目录只读绑定（只读挂载上读文件不更新 atime），只有 `暂存/<作业编号>/` 可写，工具写不到别处。
- "只读挂载不更新 atime"是按内核机制推断的，第一张跑真转换的票要用扇区数核对证实；证实不了就停下来找负责人。

### 5. 转换流程

1. 提交前：选输入数据集和数据块、工具、型号配置、输出格式（v3.0 / v2.1），用 `info` 预览文件数、时长、话题。
2. 作业第一步 `verify`，不通过就结束，诊断原样展示。
3. `convert` 输出到 `暂存/<作业编号>/`，每个作业新目录，不用 `--force`；需要 GPU 的按现有 GPU 调度占一张卡，没卡就等，不改用 CPU。
4. 结束后自动跑四层入库检查（ADR 0008：结构、计数、视频、内容）；通过自动入库，有警告人确认，不通过留在暂存区（失败和中断的目录保留 7 天）。
5. 入库：同文件系统改名、建导航层入口、写 `来源.json` 血缘记录（worker 写，只追加）。数据来源沿用输入数据集的。

### 6. 不在本里程碑做

- RobotProfile 核对（ADR 0007）：先只用工具自带的 `verify`；RobotProfile 留到 M3 之后单独定。
- 下载的 v3.0 数据导出 v2.1 的新工具：ADR 0008 说先调研有没有现成的，排在最后一张，开工前先问。

## 与 M3 的协调（2026-11-08 和 M3 会话 datasets-45 商定，M3 已按此改第 05 张，`t/m3-plan` 9c0282c）

- **血缘记录格式**：两边都用代码里现有的 `LineageRecord`（`src/rdp/jobs/navwrite/provenance.py`，拒绝未知字段），不改模型。
  - M3 人工记录：`kind="转换"`、`status="来历部分未知"`、`recorded_by.kind="人工补录"`；`inputs` 每项只写 `{"dataset_id": ...}`；`outputs=[]`，工具相关字段为空。只有人工记录能删。
  - M4 工具记录：`kind="转换"`、`status="完整"`、`recorded_by.kind="worker"`，`inputs` 带 `dataset_id` 和 `source_id`，`tool` 里加 `binary_sha256`；只追加。
- **上下游投影**：M3 按所有记录的 `inputs[].dataset_id` 投影，验收里已含 worker 写的转换记录。M4 不用再改投影和详情页。
- **新建数据集**：M4 入库新建的转换产物不写 `数据集信息.json` 的 `collection` 键（M3 第 03 张新增），和原始数据集的关系只靠血缘；建入口复用"新增数据集"的写入流程，必有链接。M3 若改了新建流程的必填项或签名，会通知 M4。
- **ADR 0008**：M3 的修订节随 `t/m3-plan` 今晚合并；M4 在其后追加，不改 M3 那节。
- **型号**：都用 `robot_model` 字符串，不建型号表。RobotProfile 两边都不做。
