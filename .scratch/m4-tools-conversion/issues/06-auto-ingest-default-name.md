## 原因

`src/rdp/jobs/conversion/_ingest_build.py` 的 `build`：先看基础默认名 `<输入名去掉 _mcap>_lerobot` 是否已有按任务入口；有就加 `_<转换作业编号>`，但 `occupied` 仍保持 True，`ingest.py` 据此判"默认名被占用"不自动入库。dataset-35 的基础默认名正好是已有的 dataset-29（`R1_lite_table_withdrawing_lerobot`），所以这个最常见的场景永远不会自动入库。存放位置的默认值同理（基础位置被占用加编号后仍判占用）。

## 期望

第 04 张工单的"默认名字或位置已被占用时不自动入库"指的是**按默认规则（冲突时加编号）得出的最终名字和位置**：
- 基础默认名被占用、加编号后的名字没被占用 → 不算占用，检查通过就自动入库；
- 加编号后的名字（或位置）仍被占用 → 算占用，等人确认；
- 用户在预览里自己填的名字、位置被占用 → 照旧报错（不变）。
