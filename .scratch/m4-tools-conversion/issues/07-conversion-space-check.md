# 转换前检查可写根剩余空间

Status: done

分级：直做（在已有模块里加功能，不改领域契约）。负责人 2026-11-08 点名："先解决M4，转换前要检查剩余空间"（遗留事项第 4 条）。合并前要负责人说"合并"。

## 背景

M4 第 05 张演练（2026-11-08 09:17）：dataset-35 一整天的数据块装不进 4 GB 的测试根，ffmpeg 报 `No space left on device`，作业跑了一段才失败。诊断完整、暂存保留、数据盘未写，但白跑了时间，暂存区里还留下一份半成品。

执行线 2026-11-08 实测（数据块只读元数据、O_NOATIME，数据盘写入扇区前后不变）：同一数据块 `20261011_table_withdrawing` 共 114 个文件、44,251,313,024 字节（41.21 GiB），产物 5.64 GB，**产物 / 输入 ≈ 0.13**。遗留事项里写的 0.08 是估错的。

## 要做的

转换作业在第 2 阶段「核对输入」做空间预检，放在现有的存储根在线检查之后、新建暂存目录之前（`src/rdp/jobs/conversion/job.py` 的 `_prepare_paths`）。

1. **输入大小**：本次选中的数据块（`source_ids`，不是整个数据集）的表观字节之和。复用 M1 的只读大小遍历（`rdp.jobs.datasets` 里的 `_size_walk` / `_size_access`，O_NOATIME，不打开数据文件），不另写一套遍历；遵守 import-linter，必要时在 datasets 包里加一个公开入口。遍历要能响应取消（`context.reporter.check_cancelled`）。
2. **可用空间**：选中的可写根当时的可用字节（`shutil.disk_usage(...).free`），经 worker 的有界存储检查器访问，写法参照 M2 下载计划的 `_capacity_snapshot`（`src/rdp/jobs/downloads/plan.py`）。测试里可注入。
3. **估算**：所需 = ⌈输入字节 × 0.25⌉ + 1 GiB 预留。
   - 0.25 约是实测 0.13 的两倍，留出编码参数、其他型号的差异；1 GiB 预留与 M2 下载一致。两者写成模块常量，注释写明来源（本节的实测）。
   - 常量的值以后按真实转换的经验再调，本票不做成配置项。
4. **不够时**：作业以外部失败结束，不建暂存目录、不调用工具（verify 也不跑）。诊断五段：
   - 规则 `conversion.insufficient_space`，对象是可写根名；
   - 实际：输入、估算产物、预留、可用，各写字节数，括号里附 GiB（两位小数）；
   - 期望：可用空间不少于估算产物与预留之和；
   - 后果：未开始转换，未建暂存目录；
   - 下一步：释放可写根空间后重新提交。
5. **够时**：行为与现在完全一样。

不做：
- 提交时（Web 侧）不预检。Web 不碰存储根（数据契约），以执行时为准。
- 预检不保证转换途中空间一直够（别的作业也在写）。途中写满仍按现有路径失败，诊断完整、暂存保留。
- 不在真实数据上演练（负责人 2026-11-08："NAS接入、真实下载、真实转换先留着，我后面会做的"）。

## 验收

1. 可用空间小于估算加预留：作业失败，诊断规则是 `conversion.insufficient_space`，实际一段包含四个数；暂存目录 `暂存/转换/<作业编号>` 没有建；工具没有被调用。
2. 只按选中的数据块估算：同一数据集里有一个没选中的大数据块，只算选中的那些也够，作业照常成功。
3. 原有转换测试照常通过，不因为加了预检而改它们的断言（需要的话只给它们注入"空间足够"）。
4. 最后一次 `make check` 全绿、0 skipped。

## 范围变更（负责人 2026-11-08 23:2x，限时 20 分钟）

负责人："检查大小的逻辑一般是 目标大小 * 百分比 + 偏置，能否让用户自己填写百分比和偏置的数值，系统拿到输入后再检查"；"Vitest、noatime 这两条可以改"；"finish within 20mins"。上面"要做的"第 3 条的常量改成用户填写的参数，其余照旧，另加三项：

1. **参数（后端）**：转换参数 `ConversionParameters` 和下载参数 `DownloadParameters` 都加两个可选字段，旧作业参数里没有时取默认值：
   - `space_ratio_percent`：整数 0–1000，转换默认 25，下载默认 100；
   - `space_reserve_gib`：数 0–1024，默认 1。
   - 所需 = ⌈目标字节 × 百分比 / 100⌉ + 偏置 GiB × 1024³。转换的目标字节是选中数据块大小；下载的目标字节是现有的"待下载量"，检查点不变（预览一次、开始下载一次），只换公式。默认值下下载的行为与现在一致。
   - 诊断"实际"一段写出用到的百分比和偏置。
2. **表单（前端）**：数据集详情的"转换"表单和下载表单的"高级参数"里各加两项：百分比（%）和偏置（GiB），预填默认值，旁边一句说明"所需空间 = 目标大小 × 百分比 + 偏置"。
3. **入库按钮（前端）**：作业详情页和转换暂存页的"检查并入库"只在转换成功（含带警告成功）时显示。负责人 23:2x 在失败的转换 1347 上点了它，得到一个误导的"输入或数据问题"（作业 1348）。
4. **没有可写根的提示（后端）**：`src/rdp/jobs/conversion/job.py` 和 `src/rdp/jobs/conversion/_ingest_read.py` 里"没有登记可写存储根"的下一步改成"管理员在配置文件登记可写存储根（NAS 平台区）后重新提交"，类别是外部问题。
5. **Vitest（前端）**：`src/web/vite.config.ts` 的 `test` 段加 `testTimeout: 15000`（遗留事项第 8 条）。本票允许改的受保护文件只有这一行。

验收补充：
5. 下载：百分比 200、待下载量刚好超过可用空间的一半 → 预览失败，诊断规则仍是 `download.insufficient_space`。
6. 前端：转换表单提交的请求体带上用户填的两个值；失败的转换作业详情页没有"检查并入库"。
