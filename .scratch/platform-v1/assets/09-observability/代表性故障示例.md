# 代表性故障示例

「[可观测性与报错规范](../../issues/09-observability.md)」的完成标准：只凭输出，就能找到出问题的对象、违反的规则和下一步该查什么。

文件名、版本号、哈希、数值都是示意，不是实测。格式是这张票定下来的格式。

## 示例一：转换作业部分成功

场景：把一次 R1 Lite 采集的 3 个 mcap 转成 LeRobot v3.0。

- 第 1 个文件正常。
- 第 2 个文件有两条警告：
  - 左臂反馈缺了一段消息，丢 3 帧并在此切分。
  - 头部相机前 12 条消息在第一个关键帧之前。
- 第 3 个文件的头部相机没有关键帧，这个文件失败。

### 运行日志（worker 的日志文件）

运行日志只记作业的开始和结束。诊断只出现在作业日志里，不在这里重复（每个错误只报告一次）。

```text
2026-10-21 16:15:02.101+08:00 INFO  rdp.jobs 作业开始 job=42 类型=转换 提交人=张三(#3) 作业日志=<作业日志目录>/20261021-161502-转换-42.log
2026-10-21 16:21:30.010+08:00 INFO  rdp.jobs 作业结束 job=42 状态=部分成功 成功=2 失败=1 警告=2 耗时=6m28s
```

## 示例二：平台自身的缺陷

场景：打开一个数据集的详情页。这个数据集 `原始路径.json` 里某条 `links` 的 `target` 是 null，平台的解析代码没有处理这种情况。漏掉这项校验，属于平台的程序缺陷。

### 运行日志（Web 的日志文件）

只在接口的统一异常处理处记一次，带错误编号和完整的异常链。

```text
2026-10-21 16:30:11.552+08:00 ERROR rdp.api 内部错误 err=7f3a2c19 请求="GET /api/datasets/r1lite_叠衣服" 账号=李四(#5)
  错误链：读取数据集 r1lite_叠衣服 的详情失败
        ← 解析 <导航层>/r1lite_叠衣服/原始路径.json 的 links[3] 失败
        ← TypeError: expected str, bytes or os.PathLike object, not NoneType
  Traceback (most recent call last):
    File ".../rdp/datasets/nav.py", line 88, in parse_links
      target = Path(raw["target"])
    ……
```

