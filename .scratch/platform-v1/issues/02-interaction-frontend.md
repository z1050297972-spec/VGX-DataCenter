# 交互形态与前端路线

Type: grilling
Status: resolved

## Question

平台以什么形态给人用，前端怎么写？

**负责人初步意见**（开图时给出，本票确认）：只做 Web，不做 CLI；前端用 React。

要定的：

- **完全不做 CLI 吗？** 这和几处已有约定冲突，需要确认怎么取舍：
  - 0003 第四节：同一组核心函数，套 CLI 和 Web 两个入口
  - 0003 第六节：CLI 用 Typer + Rich
  - 原始需求 (2)："在终端中"看网速和资源

  另外，数据库迁移、重新扫描、服务启停这类运维操作，要不要保留一个最小的命令行入口？
- **React 的具体形态**：用什么构建工具；和 FastAPI 的边界怎么划（纯 API + 单页应用）；前后端怎么一起部署；后端的类型怎么同步到前端。
- **访问范围**：只在本机用，还是允许局域网或 tailscale 多人访问；如果允许多人访问，鉴权怎么做。如果采用「[实时可视化路线](06-live-viz-route.md)」推荐的路线，Lichtblick 要用 iframe 嵌进页面，而浏览器只有在 HTTPS 或 localhost 下才能解码 H.264。所以只要允许从其他机器访问，平台就必须上 HTTPS。
- **实时推送**：作业进度、网速、M5 的实时曲线这些实时性需求，用轮询、SSE 还是 WebSocket。

**完成标准**：以上四项都有结论。前端路线写成 ADR（为什么选 React 单页应用 + FastAPI、放弃了什么）；新出现的术语写进 `GLOSSARY.md`。

## Answer

2026-10-21 与负责人逐轮确认。前端路线写成 ADR：[0001 只做 Web 的 React 单页应用](../../../docs/adr/0001-只做Web的React单页应用.md)；账号、角色、三种日志、保留期写进了 [GLOSSARY.md](../../../GLOSSARY.md)。

- **交互形态**：只做 Web。另留一个最小的运维命令入口：启动 Web 和 worker、数据库迁移、重建索引、创建首个管理员，不放任何业务功能。原始需求 (2) 的网速和资源监控改成 Web 页面。0003 第四、六节里 CLI 的部分作废；"核心函数不依赖入口"的原则保留，领域模块不 import FastAPI。
- **前端**：
  - Vite + React + TypeScript 单页应用。FastAPI 只提供 `/api/*` 下的 JSON 接口，生产环境在同一进程里托管前端构建产物，只占一个端口。开发时由 Vite 开发服务器把 `/api` 转发给后端。
  - 端口避开 80、8080、8088，这几个已被本机现有的 Docker 服务占用。
  - 前端类型由 FastAPI 的 OpenAPI 生成，`make check` 检查是否过期。
  - 前端源码放在 `src/web/`，文件归属规则不变。
  - 路由、数据获取、组件库等具体库，以及前端检查链，归「[技术栈与工程规范](03-tech-stack-standards.md)」。
- **访问范围与账号**：
  - 监听 `0.0.0.0`，多人账号。角色只有两种：**管理员**能管理账号、查看日志；**成员**能做全部业务操作。
  - 不开放自助注册。首个管理员用运维命令创建，之后由管理员在 Web 上建号、重置口令。口令只存加盐哈希（0003 的"不存密码"指机器人的 SSH 密码，不变）。
  - **记录里存名字**：操作日志、登录日志和作业记录都同时存账号的内部编号和当时的名字。账号删除以后，记录照常显示，写成"张三（已删除）"。以后新建同名账号时，内部编号不同，所以不会和旧记录混淆。
  - **管理员随时可以删除账号**，不用等保留期，删除后不能恢复。**停用**只用于暂时不让某人登录（例如休假），停用后可以恢复，不是删除的前置步骤。账号被停用或删除时，它已经登录的会话立刻失效。系统里至少保留一个启用状态的管理员。
  - 走票时一度定过"保留期内不能删账号"，后来因为记录里存了名字，这条规则失去了理由，经负责人确认取消。
  - 用删除账号之前的备份恢复数据库时，被删的账号会跟着回来。这属于正常现象，因为恢复就是把整个系统退回那个时间点。
- **日志**：
  - **操作日志**记录所有写操作：导航层的变更、机器人和采集任务登记信息的增删改、作业的提交和取消、账号管理。每条记下谁、什么时候（UTC）、做了什么、对象、结果。
  - **登录日志**记录每次登录尝试（不论成败）和每次登出，内容是账号、时间、来源 IP。
  - 两种日志都存在数据库里，只追加，界面上不能修改或删除。**保留期 30 天**，管理员可调，到期自动清除。页面只有管理员能看，成员看不到。
  - 操作日志、作业日志、运行日志三者区分开，定义见 GLOSSARY。
- **HTTPS**：M0–M4 只走 HTTP，接受口令在局域网 Wi-Fi 上明文传输的风险（tailnet 内有 WireGuard 加密）。前端地址一律写相对路径。HTTPS 属于 M5 内部，M5 开图时再定，可选做法有 `tailscale serve`、relay 转 JPEG、远程桌面。
- **实时推送**：统一用约 1 秒一次的轮询，平台里不用 WebSocket。将来某一路需要亚秒级推送时（例如 M6 的录制状态），只把这一路改成 SSE。机器人的实时画面和曲线由 Lichtblick 直连 foxglove_bridge，不经过平台后端。
- **备份**：账号、日志等数据只存在于数据库里，没法从导航层重建，所以平台要备份数据库和导航层。负责人的初步意见是放 NAS，具体方案另开票「[备份方案](17-backup.md)」。
- **里程碑**：账号、登录和两种日志都放进 M0。M1 的建链、改指向从第一天起就记操作日志。
- **对其他票的影响**（已同步到各票正文）：「核心领域模型与术语」加入账号和两种日志；「作业模型」要记录作业的提交人（按上面的办法同时存内部编号和名字）；「软链接接口规则」里的操作记录和导航层备份两项改写；「可观测性与报错规范」要和三种日志划清边界。
