# 交互形态与前端路线

Type: grilling
Status: open

## Question

平台以什么形态给人用，前端怎么写？

**负责人初步意见**（开图时给出，本票确认）：只做 Web，不做 CLI；前端用 React。

要定的：

- **完全不做 CLI 吗？** 这和几处已有约定冲突，需要确认怎么取舍：
  - 0003 第四节：同一组核心函数，套 CLI 和 Web 两个入口
  - 0003 第六节：CLI 用 Typer + Rich
  - 原始需求 (2)："在终端中"看网速和资源

  另外，数据库迁移、重新扫描、服务启停这类运维操作，要不要保留一个最小的命令行入口？
- **React 的具体形态**：用什么构建工具；和 FastAPI 的边界怎么划（纯 API + 单页应用）；前后端怎么一起部署；后端的类型怎么同步到前端。
- **访问范围**：只在本机用，还是允许局域网或 tailscale 多人访问；如果允许多人访问，鉴权怎么做。如果采用「[实时可视化路线](06-live-viz-route.md)」推荐的路线，Lichtblick 要用 iframe 嵌进页面，而浏览器只有在 HTTPS 或 localhost 下才能解码 H.264。所以只要允许从其他机器访问，平台就必须上 HTTPS。
- **实时推送**：作业进度、网速、M5 的实时曲线这些实时性需求，用轮询、SSE 还是 WebSocket。

**完成标准**：以上四项都有结论。前端路线写成 ADR（为什么选 React 单页应用 + FastAPI、放弃了什么）；新出现的术语写进 `GLOSSARY.md`。
