# 核心领域模型与术语

Type: grilling
Status: open
Blocked by: 05, 11

## Question

平台的核心领域对象有哪些，彼此是什么关系（不含子任务）？这是 M0 数据库和后续各里程碑共用的语言。数据集一侧以「[数据集板块的数据契约](11-dataset-contract.md)」为准，机器人一侧以「[两台机器人的事实](05-robot-facts.md)」为准。

要定的：

- **对象清单**：数据集、机器人（实体）、机器人型号、采集任务、受控词表（采集方式、用途、场景）、工具、作业。每个对象的身份是什么，生命周期怎样。
- **机器人身份**：用 MAC 还是序列号。IP、端口、SSH 用户作为可变属性（0003 第六节 (3)）。
- **采集任务的关系**：采集任务和机器人、数据集之间是什么关系；一次采集产出一个数据集还是多个。
- **"采集机器人型号"是不是同一个概念**：`数据集信息.json` 里的"采集机器人型号"（例如 franka、aloha、g2a），和平台登记的机器人型号是不是一回事。
- **数据来源类别**：原始需求开头列了真机采集、仿真生成、UMI、ego、开源下载。这些要不要作为数据集的属性。
- **账号和其他对象的关系**：账号、角色、操作日志、登录日志已在「[交互形态与前端路线](02-interaction-frontend.md)」定义，见 `GLOSSARY.md`。这里要定的是：哪些对象引用账号（作业的提交人、操作日志的操作人，机器人和采集任务要不要记创建人）。账号删除以后引用怎么处理已经定了：记录同时存账号的内部编号和名字，显示为"张三（已删除）"。

补充（来自「[作业模型](10-job-model.md)」，ADR 0005）：作业的身份、作业状态和提交人（账号或"系统"）已经定了，术语见 `GLOSSARY.md`。本票对象清单里的"作业"直接引用这些结论，不重新定。

补充（来自「[数据集板块的数据契约](11-dataset-contract.md)」，ADR 0006）：
- **数据集一侧的术语已定**：导航层、数据集、数据集信息、数据集索引、视图、按任务视图、按格式视图、入口、规范副本、格式、格式版本、链接、数据块、存储根、平台区、离线、断链、非数据集目录、重新扫描、统计大小、一致性面板，见 `GLOSSARY.md`。
  - 本票对象清单里的"数据集"直接用这些定义。
  - 平台对象引用数据集只用 `dataset_id`，引用数据块只用 `source_id`，两者都永久不变。
- **"采集机器人型号"的新事实**：平台扫描时会从 `meta/info.json` 读 `robot_type`（0010 第 3 节）。
  - 25 个数据集有具体的值，例如 `franka`、`aloha`、`galaxea_r1lite`、`g2a`；galaxea_open_world 有 `r1lite`、`r1pro` 两种。
  - 7 个数据集的值是 `unknown` 或 `null`。
  - 3 个数据集不是 LeRobot，没有这一项。

  `robot_type` 和平台登记的机器人型号是什么关系，由本票定。

**完成标准**：每个对象都写进 `GLOSSARY.md`（英文规范名 + 中文、定义、要避开的同义词），对象之间的关系有一张图或一张表。另外至少走过两个场景：同一台机器人换了 IP；一个开源数据集里混有多种型号的机器人。
