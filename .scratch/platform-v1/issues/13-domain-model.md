# 核心领域模型与术语

Type: grilling
Status: resolved
Blocked by: 05, 11

## Question

平台的核心领域对象有哪些，彼此是什么关系（不含子任务）？这是 M0 数据库和后续各里程碑共用的语言。数据集一侧以「[数据集板块的数据契约](11-dataset-contract.md)」为准，机器人一侧以「[两台机器人的事实](05-robot-facts.md)」为准。

要定的：

- **对象清单**：数据集、机器人（实体）、机器人型号、采集任务、受控词表（采集方式、用途、场景）、工具、作业。每个对象的身份是什么，生命周期怎样。
- **机器人身份**：用 MAC 还是序列号。IP、端口、SSH 用户作为可变属性（0003 第六节 (3)）。
- **采集任务的关系**：采集任务和机器人、数据集之间是什么关系；一次采集产出一个数据集还是多个。
- **"采集机器人型号"是不是同一个概念**：`数据集信息.json` 里的"采集机器人型号"（例如 franka、aloha、g2a），和平台登记的机器人型号是不是一回事。
- **数据来源类别**：原始需求开头列了真机采集、仿真生成、UMI、ego、开源下载。这些要不要作为数据集的属性。
- **账号和其他对象的关系**：账号、角色、操作日志、登录日志已在「[交互形态与前端路线](02-interaction-frontend.md)」定义，见 `GLOSSARY.md`。这里要定的是：哪些对象引用账号（作业的提交人、操作日志的操作人，机器人和采集任务要不要记创建人）。账号删除以后引用怎么处理已经定了：记录同时存账号的内部编号和名字，显示为"张三（已删除）"。

补充（来自「[作业模型](10-job-model.md)」，ADR 0005）：作业的身份、作业状态和提交人（账号或"系统"）已经定了，术语见 `GLOSSARY.md`。本票对象清单里的"作业"直接引用这些结论，不重新定。

补充（来自「[数据集板块的数据契约](11-dataset-contract.md)」，ADR 0006）：
- **数据集一侧的术语已定**：导航层、数据集、数据集信息、数据集索引、视图、按任务视图、按格式视图、入口、规范副本、格式、格式版本、链接、数据块、存储根、平台区、离线、断链、非数据集目录、重新扫描、统计大小、一致性面板，见 `GLOSSARY.md`。
  - 本票对象清单里的"数据集"直接用这些定义。
  - 平台对象引用数据集只用 `dataset_id`，引用数据块只用 `source_id`，两者都永久不变。
- **"采集机器人型号"的新事实**：平台扫描时会从 `meta/info.json` 读 `robot_type`（0010 第 3 节）。
  - 25 个数据集有具体的值，例如 `franka`、`aloha`、`galaxea_r1lite`、`g2a`；galaxea_open_world 有 `r1lite`、`r1pro` 两种。
  - 7 个数据集的值是 `unknown` 或 `null`。
  - 3 个数据集不是 LeRobot，没有这一项。

  `robot_type` 和平台登记的机器人型号是什么关系，由本票定。

**完成标准**：每个对象都写进 `GLOSSARY.md`（英文规范名 + 中文、定义、要避开的同义词），对象之间的关系有一张图或一张表。另外至少走过两个场景：同一台机器人换了 IP；一个开源数据集里混有多种型号的机器人。

### 对象与关系

| 对象 | 身份 | 登记什么 | 和谁有关系 | 状态 | 存在哪里 |
|---|---|---|---|---|---|
| 数据集 | `dataset_id`（ADR 0006） | 都在导航层里 | 最多属于 1 个采集任务；带若干型号标签；有一个数据来源 | — | 导航层 |
| 机器人 | 平台编号，不改，不复用 | 名称；型号；序列号；每块网卡的 MAC；地址、SSH 端口、SSH 用户 | 属于 1 个型号；参与多个采集任务 | 使用中 / 停用 | 数据库 |
| 机器人型号 | 平台编号 | 名称；对应的型号标签 | 下面有多台机器人；RobotProfile 和适用的工具挂在型号上 | 使用中 / 停用 | 数据库 |
| 采集任务 | 平台编号 | 名称；采集方式、用途、场景；说明 | 用多台机器人；产出多个数据集 | 进行中 / 已归档 | 数据库 |
| 受控词表项 | 平台编号 | 名称；采集方式的项另记它对应的数据来源 | 被采集任务引用 | 使用中 / 停用 | 数据库 |
| 工具 | 由「工具清单与转换血缘」定 | 清单 | 适用于若干型号；被作业调用 | 由同一张票定 | 工具清单 |
| 作业、账号 | 已定 | 已定 | 账号出现在：作业的提交人、操作日志的操作人、各登记对象的创建人和修改人 | 已定 | 数据库 |

例子都用真实数据：
- 型号"R1 Lite"下有一台机器人，序列号 RBB60624A002。
- 采集任务"桌面收纳"用的是这台机器人，产出了两个数据集：R1_lite_table_withdrawing_mcap（原始数据，分 10-09、10-10、10-11 三个目录），以及转换出来的 R1_lite_table_withdrawing_lerobot。
- galaxea_open_world 带 `r1lite`、`r1pro` 两个型号标签；型号 R1 Lite 对应 `galaxea_r1lite` 和 `r1lite`。

### 结论

- **机器人的身份**（Q1）：
  - 用平台分配的永久编号，不改、不复用。序列号和 MAC 都只是属性。原因：一台机器人有好几块网卡（R1 Lite 3 块，AutoLife 3 块外加一块虚拟网卡），换了网卡 MAC 就变；AutoLife 的序列号读不到，只有主机名里的 310。
  - 登记的内容：名称、型号、序列号（能填就填）、每块网卡的 MAC。原始需求里的"类型"就是型号。
  - 连接信息有三项：地址（IP 或主机名）、SSH 端口（默认 22）、SSH 用户，随时可以改，不影响身份。原始需求里的"端口"按 SSH 端口理解；预览、录制用的其他端口，归「RobotProfile 是否共用」和 M5。
  - 平台不存密码。R1 Lite 现在只能用密码登录，平台怎么连上它，留到 M5。
- **型号和型号标签是两个概念**（Q2）：
  - 机器人型号是我们自己拥有的机器人的型号。型号标签是数据里自带的字符串，例如 LeRobot 的 `robot_type`，大多数不对应我们拥有的机器人，不登记成型号。
  - 型号上可以写明它对应哪些标签，这样按型号筛选时，开源数据里同型号的数据也能筛出来。
- **采集任务的关系**（Q3）：
  - 采集任务和机器人是多对多。
  - 一个采集任务可以产出多个数据集；一个数据集最多属于一个采集任务。开源下载的数据集不属于任何采集任务。
  - 转换出来的数据集和它的原始数据集之间，是血缘关系，归「工具清单与转换血缘」。
  - 一次录制（录制会话、episode）怎么进数据集，M6 开图时再定。
- **受控词表**（Q4）：
  - 共三个：采集方式、用途、场景。每个采集任务在每个词表里各选一项。
  - 成员可以新增、改名、停用词表项。改名不影响已经引用它的任务；被引用过的项不能删除，只能停用。
  - 初始取值在 M3 开工时定。
- **数据来源**（Q5）：
  - 它是数据集的属性，意思是"这份数据是怎么进到平台的"。取值：真机采集、UMI 采集、ego 采集、仿真生成、开源下载、未知。开源下载来的仿真数据算开源下载。
  - 平台自己产出的数据集，自动确定：采集任务产出的，按采集方式对应的来源；下载作业入库的，算开源下载。现有的 35 个数据集，由人一次性标注。
  - 这个属性存在哪里，和血缘一起在「工具清单与转换血缘」定。
- **创建人与删除**（Q6）：
  - 机器人、型号、采集任务、词表项，都记下创建人、创建时间、最后修改人和最后修改时间，长期保留。账号删除后，显示成"张三（已删除）"。
  - 被引用过的对象不硬删：机器人、型号、词表项可以停用，采集任务可以归档。停用和归档之后，新建时的选项里不再出现，历史记录照常能看。
- **四条细则**（负责人确认）：
  1. 一个型号标签最多对应一个型号。
  2. 机器人、型号、采集任务的名称，各自不能重复。
  3. 没被引用过的对象，例如登记错了的，可以直接删除；被引用过的，只能停用或归档。
  4. 新建采集方式的词表项时，要选好它对应哪种数据来源。

### 场景一：同一台机器人换了 IP

1. R1 Lite 原来的地址是 DHCP 分配的 192.168.0.229，路由器重启后变成了 192.168.0.231。
2. 它的平台编号、名称、序列号、MAC 都没变，引用它的采集任务、作业记录都不受影响。
3. 下次连接时连不上旧地址，平台报一条诊断"连不上 192.168.0.229:22"，下一步提示去改地址。有人改了地址后，操作日志记一笔，机器人的"最后修改人"跟着更新。
4. 可选功能：按登记的 MAC 在局域网里找到新地址，提示要不要更新。做不做由 M5 定。

### 场景二：一个开源数据集里混有多种型号

1. galaxea_open_world 的 227 份 `info.json` 里，`robot_type` 有 `r1lite`、`r1pro` 两种。扫描后，索引里这个数据集带有这两个型号标签。
2. 按标签 `r1pro` 筛选，能筛到它。按型号 R1 Lite 筛选，因为 R1 Lite 对应 `galaxea_r1lite` 和 `r1lite`，所以能筛到它，也能筛到 R1_lite_table_withdrawing_lerobot。
3. 它不属于任何采集任务，也不关联任何一台机器人。数据来源要由人标注成"开源下载"。
4. 我们没有 R1 Pro，所以 `r1pro` 只作为标签存在。以后如果买了 R1 Pro，登记型号时把 `r1pro` 对应上，已有的数据集就能按这个型号筛到，不用改任何数据。

### 风险

- **现有数据集的数据来源要人工标注**：35 个数据集都要标一遍，标完之前，按来源筛选只能看到"未知"。在哪里标、怎么标，由「工具清单与转换血缘」定。
- **AutoLife 还没有序列号**：要等有人用 root 读一次 DMI。在那之前，登记时只能先填主机名里的 310，或者留空。
