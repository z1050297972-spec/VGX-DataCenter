# 软链接接口规则

Type: grilling
Status: open
Blocked by: 04, 10, 11

## Question

平台怎么写导航层？以 0003 4.4 为起点；读取的那一面以「[数据集板块的数据契约](11-dataset-contract.md)」为准，并发和日志以「[作业模型](10-job-model.md)」为准。

要定的：

- **建链**：
  - 0003 4.4 推荐的五条校验规则定稿
  - 写回 `原始路径.json` 的 `links` 和 `sources` 时遵守什么规则
  - 两个视图是否同步建链
- **新增数据集**：是否一次就建好两个视图的目录、链接和三个 JSON 的骨架。
- **改指向**：智元数据迁到 NAS 时的批量换前缀，参考「[NAS 接入事实](04-nas-facts.md)」；两个视图联动修改；先预览、再确认。
- **体检**：只报告、不修复，具体覆盖哪些检查。
- **原子性**：链接和清单两者中有一个写失败时，怎么回滚。
- **操作记录**：建链、改指向的记录是否沿用 `日志/` 的约定（例如 `日志/链接/`）；记录哪些字段；能不能凭记录回滚。
- **导航层备份**：导航层只在系统盘上，没有任何备份（F1）。要不要把 JSON 和链接清单纳入一个独立的 git 仓库，或者定期做快照？

**完成标准**：以上各项都有结论，至少走过三个场景：建链时目的路径已存在；改指向改到一半时断电；系统盘损坏后恢复导航层。写入与回滚策略写成 ADR；新出现的术语写进 `GLOSSARY.md`。
