# 软链接接口规则

Type: grilling
Status: open
Blocked by: 04, 10, 11

## Question

平台怎么写导航层？以 0003 4.4 为起点；读取的那一面以「[数据集板块的数据契约](11-dataset-contract.md)」为准，并发和日志以「[作业模型](10-job-model.md)」为准。

要定的：

- **建链**：
  - 0003 4.4 推荐的五条校验规则定稿
  - 写回 `原始路径.json` 的 `links` 和 `sources` 时遵守什么规则
  - 两个视图是否同步建链
- **新增数据集**：是否一次就建好两个视图的目录、链接和三个 JSON 的骨架。
- **改指向**：智元数据迁到 NAS 时的批量换前缀，参考「[NAS 接入事实](04-nas-facts.md)」；两个视图联动修改；先预览、再确认。
- **体检**：只报告、不修复，具体覆盖哪些检查。
- **原子性**：链接和清单两者中有一个写失败时，怎么回滚。
- **操作记录**：「[交互形态与前端路线](02-interaction-frontend.md)」已定，建链、改指向都写进**操作日志**（数据库，保留 30 天）。这里要定的是：操作日志里要记下哪些字段，才能凭它撤回一次改动；超过 30 天的改动还要不要另留一份记录。
- 导航层备份已移到「[备份方案](17-backup.md)」。

补充（来自「[作业模型](10-job-model.md)」，ADR 0005）：
- **写操作都是作业**：建链、新增数据集、改指向，都由 worker 在导航层写锁下执行，Web 不直接写导航层。单条建链正常 1–2 秒出结果。
- **预览时的状态**：写导航层的作业在提交时记下预览时看到的状态，执行前再核对一次，对不上就以"冲突"失败，一行都不写。本票要定这个"状态"具体记什么（例如相关 `原始路径.json` 的内容哈希、链接当前的指向），以及核对哪些范围。
- **中断后的恢复流程**：写导航层的作业被中断（断电、worker 崩溃）后会标成已中断。worker 重启时先跑它的恢复流程，跑完才放行别的写操作。本票的"原子性"一项和"改指向改到一半时断电"场景，要给出这个恢复流程：是回滚还是补完，以及凭什么判断已经做到了哪一步。

补充（来自「[数据集板块的数据契约](11-dataset-contract.md)」，ADR 0006）：
- **改写范围比"改 `原始路径.json`"大得多**：
  - 数据盘的绝对路径在三种 JSON 里都有。两个视图合计，`原始路径.json` 里有 7,634 处，`子任务.json` 里有 16,908 处，`数据集信息.json` 里有 608 处，后者在第 2 项"地址"和第 14 项"信息来源与核验日期"的 Markdown 正文里。
  - 光 agibot_world_2026 一个数据集就约 6,900 处，分散在 6 个文件里。
  - 已定：改指向时按前缀替换，覆盖所有表示"现在的位置"的地方，包括 `direct_path`、链接的 `source_path`、`dataset_roots`、子任务里的路径和 Markdown 里的路径；跳过 `original_path`。Markdown 里的每一处替换都列进预览。
  - 本票要定替换的边界规则，例如前缀后面必须紧跟 `/` 或者是字符串结尾。
- **字段规则已定**：
  - `original_path` 不改，`source_id` 不重算。
  - 能推出来的字段（`entry_path`、`view`/`format`/`version`）在写入时由平台重新生成。
  - 不认识的字段原样保留。
  - 本票要定：写回时，要不要顺手给 `数据集信息.json` 补上缺的 `schema_version`，要不要把省略的 `version` 写成 `null`。
- **副本**：写入时先改按任务入口（规范副本），再由它生成按格式入口的各份。本票要定生成规则：
  - 按格式入口只保留"该格式那一部分"时，数据块和子任务怎么筛选。EgoProDemo 是现成的例子。
  - 链接够不着的数据块怎么处理。例如 alpha 有 3 个这样的数据块，它们的 `entry_path` 是绝对路径。
- **体检就是一致性面板**：检查清单写在「数据集板块的数据契约」的 Answer 里，本票不再定"体检覆盖哪些检查"。
- **写入之后**：在同一个作业里更新受影响数据集的索引，并提交一次统计大小。
- **预览时记下的状态**：重新扫描在第二段提交结果时，也要判断这期间数据集有没有被改过。两处用同一种状态，例如入口里三份 JSON 的内容哈希，加上各链接的指向。
- **数据集编号**：`dataset_id` 不复用。本票要定：
  - 新增数据集时，编号怎么分配。
  - 如果做"移除数据集"（只移除导航层入口，不删数据），之后怎么保证编号不会被重新分配出去。索引可以重建，所以这份记录不能只放在数据库里。
- **存储根**：链接目标可以在只读的存储根下，因为链接只是指向它；但新产物只能写进可写的存储根，也就是平台区。

补充（来自「[核心领域模型与术语](13-domain-model.md)」）：新增数据集时，要写入它的数据来源，例如下载入库的写"开源下载"。写在哪里，由「工具清单与转换血缘」定。

**完成标准**：以上各项都有结论，至少走过三个场景：建链时目的路径已存在；改指向改到一半时断电；改指向 40 天后发现指错了，要撤回（此时操作日志已经清掉）。写入与回滚策略写成 ADR；新出现的术语写进 `GLOSSARY.md`。
