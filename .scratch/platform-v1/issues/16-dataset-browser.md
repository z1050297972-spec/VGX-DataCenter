# 数据集浏览界面

Type: prototype
Status: resolved
Blocked by: 01, 02

## Question

数据集浏览界面应该长什么样、怎么用？参考 0003 的 4.2 和 4.3。

用「[盘点导航层的 70 份 JSON](01-nav-json-inventory.md)」得到的真实数据（只读导出的副本），按「[交互形态与前端路线](02-interaction-frontend.md)」定的前端路线，做一个粗糙的原型，让负责人对着它确认布局和交互：

- **两棵树**：按格式、按任务两个页签，带数据集数量和总大小。
- **数据集列表**：支持筛选。
- **详情页**：展示三个 JSON。`子任务.json` 最大约 14 MB，要按需加载。
- **跨视图跳转**：从一个视图跳到同一数据集在另一个视图里的位置。
- **一致性面板**。

原型放在 `prototype/<名>` 分支，不合入 main；本票只放链接。

补充：前端栈已定（ADR 0002），原型用 Ant Design 做，这样负责人对着原型确认的布局可以直接用到 M1。

补充（来自「[数据集板块的数据契约](11-dataset-contract.md)」，ADR 0006）：原型按下面这些已定的规则做，细节见那张票的 Answer 和 `docs/manual/导航层手册.md`。
- **列表和树**：
  - 读索引。
  - 大小用统计值；没统计过的，用 10-12 的记录值，并标出来。
  - 筛选用的机器人型号和 FPS 来自 `meta/info.json`，读不到的归为"未知"，现在有 10 个。FPS 按四舍五入后的整数来筛。
- **详情页**：
  - 三份 JSON 打开时直接读文件，`子任务.json` 点开才加载。
  - 链接状态显示扫描时的结果和检查时间，旁边有"重新检查"按钮。
  - 大小显示统计值和统计时间，并排显示 10-12 的记录值。
  - `validation_status` 配中文标签。
  - 文件比索引新时，顶部给出提示。
- **一致性面板**：
  - 四组两级，同类问题合并显示。
  - 按现在的数据，第一次扫描预计报出 1 类需要处理、5 类提示，这些内容可以直接当作原型数据。
- **存储根离线**：面板顶部报一条，链接标"存储根离线"。原型里也要体现这种情况。

补充（来自「[核心领域模型与术语](13-domain-model.md)」）：负责人看原型时一起讨论这两点：
- 筛选里要不要加"数据来源"。现有 35 个数据集还没有标注，原型里会全部显示为"未知"。
- 除了按型号标签（`robot_type`）筛选，要不要再加一个"按机器人型号"筛选。例如选了 R1 Lite，就把带 `galaxea_r1lite`、`r1lite` 标签的数据集都筛出来。

**完成标准**：负责人对着原型确认了布局，以及上面每个部件的取舍。确认结果写在本票 Answer 里，供 M1 spec 使用。

## Answer

2026-10-22 定稿。原型在 `prototype/dataset-browser` 分支的 `7bbf3f7`（不合入 main），工作目录是 `~/桌面/robot-data-platform.wt/prototype-dataset-browser`。原型用的数据由 `../assets/16-dataset-browser/export_data.py` 从导航层只读导出，不进 git。运行方法：在 `src/web/` 下执行 `pnpm dev`，然后访问 `/?variant=A`（或 B、C）。

- **布局：A、B、C 三种都保留**，用户可以切换，不合并成一套。负责人原话："A、B、C三种我都喜欢"；"先保留这样吧，不汇总成一套了"。
  - **A 三栏**：视图树、列表、连续展示的详情页；一致性面板在顶栏切换。
  - **B 树形大表加抽屉**：抽屉约占 60% 宽，按概览、14 项、数据块、子任务、其他字段分页签；一致性面板折叠在表格上方。
  - **C 文件管理器式**：路径栏加逐级目录分栏，选中哪个 JSON 文件就显示它的内容；一致性面板在右侧。
  - **给 M1 spec 的约束**：三种布局共用同一套状态（筛选、选中的数据集），以及同一套部件（详情各块、一致性面板、JSON 查看器、筛选栏）。布局之间只有排布不同，部件只写一份。切换时筛选和选中项保留，和原型一样。用户上次选的布局按账号记住。代价是 M1 的前端测试要覆盖三种布局，比单一布局多一些工作量。
- **筛选加"数据来源"**：现在全部显示为"未知"，等按「工具清单与转换血缘」标注完以后才有用。
- **按机器人型号筛选**：默认筛选项。型号标签（`robot_type`）放进"更多筛选"，没登记型号的标签（比如开源数据里的）在那里按原始字符串选。
- **其余部件都按原型保留**：
  - 两棵树，带数量和大小
  - 跨视图跳转
  - `子任务.json` 点开才加载（在工作线程里解析）
  - 链接状态旁边的"重新检查"按钮
  - 大小显示统计值，并排显示 10-12 的记录值
  - 存储根离线的提示
  - 一致性面板分四组两级，同类问题合并显示
- **原型里发现的、留给 M1 的问题**：生产构建的主包约 1 MB，超出 Vite 默认的 500 kB 警告线，M1 要按路由拆包。
