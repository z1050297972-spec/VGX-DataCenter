# 平台 v1 地图

Label: wayfinder:map

## Destination

M0 和 M1 所需的决策全部关闭，两份 spec 可以直接交给 `/to-spec`；会反过来约束底座（领域模型、数据库、模块边界）的跨里程碑决策已经落定，后续里程碑开工时不需要推翻 M0/M1。M2–M6 的范围先沿用 `docs/brief/0003-初步建议与开图草案.md` 第九节的里程碑表，各自开工时另开新图细化。

## Notes

- 领域：机器人数据管理平台。原始需求、环境事实（F1–F10）和已批准方案在 `docs/brief/0001`–`0003`。0003 里的设计只是推荐答案，以本图决策票的结论为准。
- 开图时负责人已经给出的初步意见，写在对应票正文的「负责人初步意见」里。走票时只做确认和补全，不从头重问。
- 硬性约束见 `AGENTS.md`：不参考两个旧项目；导航层是数据集的事实来源，数据盘只读；盘点和调研对 `/mnt` 一律只读。
- grilling 票同时调用 `grilling` 和 `domain-modeling`。涉及录制、同步、转换的票（「RobotProfile 是否共用」「工具清单与转换血缘」）再加调 `algorithm-engineering`。
- research 票的结果直接写到 main 的 `docs/research/<主题>.md`，不用 `research/<名>` 分支，因为本仓库没有远程。prototype 放在 `prototype/<名>` 分支，不合入 main。
- task 票采集到的环境事实，写成 `docs/brief/000N-环境事实更新-<主题>.md`。
- 本图只做规划，不写平台代码。实现一律派给 Codex；规划文档只由 Claude 修改。
- 文档写法：中文正文 + 英文标识符；术语表条目写成"英文规范名 + 中文"。
- 手册写在 `docs/manual/`。导航层手册随数据集相关的票（「软链接接口规则」等）更新；使用手册和运维手册放进每个里程碑的验收。API 文档用 FastAPI 自动生成的 OpenAPI，不手写。
- 写 M0 的 spec 时，作业框架的骨架之前先核对能用 SQLite 的现成任务队列（例如 huey），结论补进 ADR 0005（`AGENTS.md` 规则 7"先用现成的"）。

## Decisions so far

- [实时可视化路线](issues/06-live-viz-route.md)：推荐在机器人上跑 foxglove_bridge 和自写的 `viz_relay`，把话题规整到 `/viz/*`；工作站自托管 Lichtblick，用 iframe 嵌进 React 页面。Wi-Fi 上只走 TCP，不走 DDS。备选是 Rerun。R1 Lite 头部相机是 H.264，需要改装成 CompressedVideo 才能显示。
- [平台统一的 LeRobot 版本](issues/07-lerobot-version.md)：推荐以 v3.0 为唯一规范格式，配 lerobot 0.6.1（必须同时锁定库版本）；v2.1 只作为按需导出的派生格式，因为 openpi、GR00T、Galaxea、智元自家的训练代码只读 v2.1。
- [盘点导航层的 70 份 JSON](issues/01-nav-json-inventory.md)：schema 稳定，84 条链接与 `links[]` 一一对应，无断链。但有三处与 0002 不符：`按格式` 视图可以只是数据集的一部分，不一定是副本（2 例）；智元的 3 个目录被删除后 JSON 没有同步；`解压样本/` 在系统盘上放了 224 GB 真实数据。更正写在 0005。假导航层样本选了 5 个数据集。
- [交互形态与前端路线](issues/02-interaction-frontend.md)：只做 Web，另留一个最小的运维命令入口；Vite + React + TS 单页应用，由 FastAPI 同进程托管（ADR 0001）。监听 `0.0.0.0`，多人账号（管理员、成员），操作日志和登录日志保留 30 天、只有管理员能看。记录同时存账号的内部编号和名字，所以账号随时可删。M0–M4 只走 HTTP，推送用约 1 秒轮询。账号和日志进 M0；备份另开「备份方案」票。
- [技术栈与工程规范](issues/03-tech-stack-standards.md)：
  - **技术栈**（ADR 0002）：Python 3.12 + uv 的模块化单体，原生运行；SQLite + 同步写法的 SQLAlchemy 2。前端用 pnpm、TanStack Router/Query、Ant Design。平台运行时不依赖 lerobot（ADR 0003）。
  - **检查链**：ruff、basedpyright 严格模式、import-linter、契约检查脚本，全部汇总进 `make check`，由 git 钩子触发。docstring 写六项，小节标题用英文、内容写中文。负责人新增一条总需求："充分的中文注释"。
  - **流程**：Codex 不能提交，一律由 Claude 提交；新增依赖由 Claude 在负责人批准后安装。
- [两台机器人的事实](issues/05-robot-facts.md)：在 104 上，工作站直连两台机器人，头部 H.264 原样转发够用，整份录制流实时拉不动。R1 Lite 的原厂录制有 52 个话题，默认开着往厂商云（TOS）上传，厂商自带 WebRTC 网关。AutoLife 的 DDS 只绑回环，没有图像话题，采集器还没正式用过。R1 Lite 的实时话题因为 DDS 发现配置的问题没测到，转「[机器人现场补测](issues/18-robot-facts-followup.md)」。事实写在 0007。
- [Codex 协作规程](issues/08-codex-workflow.md)：每张实现票在单独的 worktree 里做，一次只做一张，规划可以并行；骨架关卡给负责人一页五块摘要，测试清单随骨架一起交；改变含义的契约变更要回到负责人那里；打回 3 轮不过就找负责人；所有提交由 Claude 做，打回期间不提交、只拍快照。联网调研也派给 Codex（只读沙箱加联网搜索）；结论性事实由 Claude 重跑或核对来源。续接会话会在执行命令时所在的目录里工作，实测见 0009。
- [可观测性与报错规范](issues/09-observability.md)：
  - **日志**：运行日志用标准库 logging，每条一行文本、带 key=value，Web 和 worker 各写一个文件，保留 30 天。
  - **诊断**：固定五段，即对象、规则、实际与期望、后果、下一步。
  - **报错**：按该由谁处理分四类，只在边界报告一次，所有登录账号都能看完整报错。
  - **作业结果**：成功、带警告成功、部分成功、失败，共四种，由计数算出。
  - **工具**：工具按同一套格式，经单独的通道上报。使用者看到的是一个系统（ADR 0004）。
  - 代表性故障示例负责人已过目。
- [作业模型](issues/10-job-model.md)：
  - **执行**：作业由独立的 worker 执行，worker 也是唯一写导航层的进程；Web 只做当场能完成的事，以及提交、取消作业。两个进程都是 systemd 用户服务，只通过 SQLite 里的作业表联系（ADR 0005）。
  - **导航层写锁**：整个导航层一把锁，只在写的那一步持有。执行前核对预览时看到的状态，对不上就以冲突失败。
  - **中断**：每类作业声明一种恢复方式。下载续跑，重新扫描重跑，转换和写导航层的作业标记中断。
  - **并发**：每类作业默认一次跑一个，不同类型之间可以并行。GPU 由 worker 分配，一张卡同一时间只给一个作业。
  - **日志**：作业日志是状态目录里的文件，保留 30 天；作业记录永久保留。
  - **里程碑**：worker 框架放进 M0。
- [数据集板块的数据契约](issues/11-dataset-contract.md)：
  - **事实来源**：导航层是唯一事实来源，数据库只放能重建的索引；`dataset_id`、`source_id` 永久不变（ADR 0006）。
  - **视图**：按任务入口的三份 JSON 是规范副本；按格式入口是"该格式下能直接用的那一部分"，可以有 0 到多个。
  - **格式不改**：现有 JSON 的冗余由平台在读写规则里消化；改指向要覆盖三种 JSON，包括 Markdown 正文。
  - **存储根**：在线 = 挂着且挂的是登记的那块盘，访问带超时；离线不算断链。只有 NAS 上的平台区可写，`AGENTS.md` 硬性规则 1 已改。
  - **扫描与面板**：每 10 分钟重新扫描一次，只在读导航层的 0.2 秒里持锁；大小由每晚的统计作业算；型号和 FPS 读 `meta/info.json`；一致性面板分四组、两级；网页不碰存储根。
  - **另定两条**：新增 `docs/manual/`，导航层手册已写初版；`AGENTS.md` 规则 7 加上"先用现成的"。
- [核心领域模型与术语](issues/13-domain-model.md)：
  - **机器人**：用平台分配的永久编号作身份，序列号、MAC 只是属性；地址、SSH 端口、SSH 用户随时可改。
  - **型号和型号标签**：机器人型号是我们拥有的机器人的型号；型号标签（`robot_type`）是数据里自带的字符串，型号可以声明自己对应哪些标签。
  - **采集任务**：和机器人多对多；一个任务产出多个数据集，一个数据集最多属于一个任务。用途、采集方式、场景三个受控词表。
  - **数据来源**：作为数据集的属性，取值有真机采集、UMI 采集、ego 采集、仿真生成、开源下载、未知。存在哪里，和血缘一起在「工具清单与转换血缘」定。
  - **登记对象**：都记创建人和修改人；被引用过的不硬删，只停用或归档。

## Out of scope

- **hf-mirror 下载机制调研、下载流程与入库到导航层**：只影响 M2 内部的做法，M2 开工时另开新图。
- **实时预览 spike**：属于 M5 内部，M5 开工时另开新图。本图只定路线（「实时可视化路线」）和映射是否共用（「RobotProfile 是否共用」）。
- **录制状态机**：属于 M6 内部，M6 开工时另开新图。
- **录制会话作为领域对象**：一次录制（录制会话、episode）怎么建模，怎么进入数据集，属于 M6 内部，M6 开图时定（「核心领域模型与术语」）。
- **按 MAC 找机器人的新地址**：机器人换了 IP 以后，按登记的 MAC 在局域网里自动找到新地址。这属于 M5 的连接功能，M5 开图时定（「核心领域模型与术语」）。
- **平台的 HTTPS**：只有 M5 会受影响（非 localhost 的浏览器解不了 H.264），M5 开图时再定。本图只定 M0–M4 走 HTTP、前端地址一律写相对路径（「交互形态与前端路线」）。
- **模型训练、数据标注**：不在平台范围内。
- **导航层 JSON 的新版格式**：把路径改成相对路径、不再存能推出来的字段、两个视图只存一份。本图决定不改现有格式（「数据集板块的数据契约」，ADR 0006），等平台当了一段时间唯一写者之后，另开一次再评估。
