# 页面布局优化：追问记录

负责人 2026-11-01："信息足够充分，但现有布局信息密度大，看上去扎堆"。目标是不删信息，解决层次、分组和留白的问题。参考资料：子 agent 对 awwwards Belgrade Arbor 的分析，在 scratchpad `research/belgrade-arbor.md`（只借鉴结构，不借鉴营销站的低密度和动效）。

## 已定（负责人："按你的推荐来"）

1. 范围：tsx 只许改布局容器，也就是套容器、分组、调顺序。不改逻辑、文案和接口，现有测试一律不改、原样通过。
2. 手段：以分组和留白为主；只有排查问题时才看的次要信息才收起，收起时要显示摘要（例如条目数）。
3. 第一批：数据集浏览页、作业列表和详情、新建数据集表单。第二批：审计和其他页面。`accounts`、`jobs` 的内联 style 清理一并做（M2 已合并）。
4. 尺寸：以桌面 1440 宽为主，1280 宽也要舒服；手机只保证能用、不错位。
5. 数据集浏览页的 A/B/C 三套布局：只细调默认的 A；共用部件改了，B 和 C 自动受益。
6. 分组：浅灰底色，每组一张白色圆角卡片，组间距大。卡片内再细分时用小标题加细分隔线，不用卡片套卡片。
7. 间距：`--rdp-space-1..8` 已有，但档位是 4/6/8/12/16/18/20/24，太碎，最大只到 24，这是扎堆的原因之一。收成 4/8/12/16/24/32/48 七档，按新档位重新映射，写进规范；`--rdp-width-*` 这类按数值命名的变量合并成语义名字。
8. 表格：antd 中等行高；长名称单行截断，悬停显示全文；路径这类要复制的列完整显示，用等宽小字号。
9. 评审方式：在隔离的预览实例上做数据集页的 2–3 个变体，截图成 PNG 给负责人比较；选定后再开第 03 张票。
10. 页头：两级，上面一行灰色小标签标位置，下面一行大标题；卡片内的分组标题只用一级。
11. 按钮：全部保持可见。每块只有一个主样式按钮，其余是次要按钮或文字按钮，放在卡片右上角。不用"更多"菜单，菜单会让按名字找按钮的测试失败。
12. 新建数据集表单：编号分段卡片，仍然一页从上往下填；不改成分步向导（那是流程变更）。
13. 作业详情页：四张卡片，依次是概要、参数、日志、诊断。诊断默认收起，标题上显示条数，收起的内容仍在 DOM 里；某个测试要求默认可见的就不收。作业列表页只调表格和间距。
14. 底部菜单（dock）：这一轮不动。
15. 原型：数据集页做三个变体给负责人比较。V1 三栏精修；V2 两栏，说明挪到页头下方做一行提示；V3 是 V2 加筛选工具条，筛选收进卡片、标签在上、吸顶。实现方式是预览实例注入 CSS，仓库代码不动。原型文件在 `~/.cache/rdp-ui-preview/`：`variants/` 放 CSS，`shots/compare/` 放截图；v0 是现状。
16. 共识已确认（负责人："按你的推荐来"）。
17. 组件（负责人 2026-11-02："使用开源的组建库，不要自己写组件了"；确认"是"）：页面结构用 antd 现成组件搭，不自己写组件，也不用 CSS 拼结构；不引入新组件库。原型里用 CSS 拼的结构，正式实现时一律换成 antd 组件。
18. 选定（负责人 2026-11-02："是，V3 加 shadcn 质感"）：数据集页用 V3。质感参考 shadcn/ui：细边框代替阴影，黑白灰为主，强调色只给主按钮和选中状态。各库截图在 `~/.cache/rdp-ui-preview/libs/`。规则写进 CODING_STANDARDS 10.14、10.15，ADR 0010 有补充。
19. 拆票：第 03 张做全局质感、间距档位和数据集浏览页；第 04 张做作业列表和详情、新建数据集表单，以及 accounts/jobs 的内联 style 清理（依赖第 03 张的变量）。
