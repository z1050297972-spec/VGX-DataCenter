# M2 开源下载 spec

Status: accepted（2026-10-30，负责人在执行线会话里回答了 4 条开工问题，见"负责人决定"）

## 目标

M2 结束时：

- 成员在网页上填一个 Hugging Face 仓库（数据集或模型权重），平台先给预览：版本（commit）、文件数、总大小、要不要视频/哪几路相机、目标存储根够不够放。
- 确认后提交"下载"作业。worker 经 hf-mirror.com 下载，用 aria2（RPC 模式）、curl 兜底；进度、速度、取消、运行中调限速都能在网页上看到和操作。
- 取消、断电、升级后重新提交，接着已经下好的部分继续，不从头下。每个文件下完都校验（sha256 或 git blob sha1，加大小）。
- 网页上能看到网络和资源状态：镜像现在是否生效、有没有开着 VPN/代理、网速、CPU/内存/磁盘/GPU 占用。
- 数据集下载完成后入库到导航层（第 05 张，等 M1 第 08 张合并后细化）。

## 负责人决定（2026-10-30，执行线会话）

1. **下载落点**：负责人原话"目前NAS还没到，之后会落到NAS上，在开发过程中可以下载一些小容量的文件作为测试，放到系统盘的/tmp下，我之后重启就没了"。
   - 代码按"可写存储根"写，不写死路径；NAS 到了只改配置，ADR 0006 不改。
   - 开发和演练只下小样例（`lerobot/pusht`，7.7 MB），放 `/tmp` 下。注意 `/tmp` 是 tmpfs，占的是内存，本机内存紧张，演练不下超过几十 MB 的东西。
2. **暂存目录**：按"数据集 + 版本"命名、只人工清理（采用调研 §6 第 3 条建议）。即 `<可写存储根>/暂存/下载/<repo 类型>/<repo_id>@<commit 前 12 位>/`，重新提交时复用；不自动删除。这一条覆盖 ADR 0008 对下载的 `暂存/<作业编号>/` 和"7 天"，第 05 张合并时补一条 ADR 修订。
3. **部分下载**：可以不要视频，或者不要某几路相机，入库时在 `来源.json` 记下筛选规则；"只下部分 episode"这次不做（调研 §6 第 4 条建议）。
4. **gated 数据集**：支持，token 交给镜像（负责人选"支持，token 交给镜像"）。平台在状态目录里存一个 token 文件（权限 0600），不进数据库、不进日志、不进作业参数；只有管理员能设置和清除，页面只显示"已设置/未设置"。
5. 调研 §6 第 5 条（并发和限速）负责人没单独问，按建议定：下载作业类型并发上限 1；单作业内 aria2 同时 4 个文件、每文件 4 条连接；全局限速默认不限，作业参数可设，运行中可调。
6. **下载参数可视化、可调**：负责人原话"hf的下载功能，本质上是通过终端的一组命令运行，其他可以选择参数，但是放在我们的平台上，我也想其中的参数可视化，并且让用户能够调节，就比如-x，-j之类的"。执行线建议如下（负责人未提异议前按此做）：
   - 作为下载作业参数开放，提交表单"高级参数"里逐项显示含义、默认值、范围；作业详情显示实际生效值。

     | 参数 | aria2 选项 | 默认 | 范围 | 运行中可改 |
     |---|---|---|---|---|
     | 同时下几个文件 | `-j` | 4 | 1–16 | 是（`changeGlobalOption`） |
     | 每服务器连接数 | `-x` | 4 | 1–16 | 否 |
     | 每文件分段数 | `-s` | 4 | 1–16 | 否 |
     | 最小分段大小 | `-k` | 20M | 1M–1G | 否 |
     | 总限速 | `--max-overall-download-limit` | 不限 | 0 或 ≥1K/s | 是 |
     | 重试次数 | `--max-tries` | 5 | 1–20 | 否 |
     | 重试间隔 | `--retry-wait` | 10 秒 | 0–600 秒 | 否 |
   - curl 兜底沿用同一限速和重试次数。运行中不能改的参数，要改就取消后重新提交，续传不受影响。
   - 落在第 02 张（参数模型、范围校验、传给 aria2、运行中修改）和第 03 张（表单、说明文案、作业详情显示）。

## 验收（里程碑级）

- 在真实部署之外的演练环境里，负责人关掉 VPN 后，从网页下载 `lerobot/pusht` 到 `/tmp` 下的测试存储根：预览正确，作业成功，文件逐个校验通过。
- 开着 VPN 时提交，作业在下载开始前以"网络不满足：镜像不生效"失败，并提示怎么处理。
- 下到一半取消，重新提交，已完成的文件跳过、半截文件续传（日志可证）。
- 下到一半杀掉 worker（模拟断电），worker 重启后作业按"续跑"恢复。
- 网络与资源页面显示的 VPN 状态和网速，与 `ip -br link`、`/proc/net/dev` 一致。

## 风险

- `/tmp` 是 tmpfs，下大文件会吃内存，可能触发 OOM（本机出现过退出码 137）。演练只用 pusht。
- 镜像限流（429）、TLS 偶发失败（调研实测 10 次 2 次）：列清单和下载都要有限次重试。
- 超过 50 GB 的单文件、aria2 跟随 302 时是否把 token 带到 CDN：调研未核对，第 02 张演练时核对能核对的部分，其余记进风险。
- 存储根"在线"按挂载表判断（ADR 0006），`/tmp` 下的测试目录不是独立挂载点：第 02 张演练环境怎么登记测试存储根，在第 01 张骨架关卡里定。
