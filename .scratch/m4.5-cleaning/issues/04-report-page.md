# 清洗报告页面与"进行转换"按钮

Status: not-started

分级：直做（前端，接口契约在第 02、03 张）。依赖：第 02 张（预览接口）；第 03 张的"进行转换"接口可先按本票写的契约用临时类型，执行线生成类型后换掉。决定见 `../decisions.md`。

## 背景

负责人："可以给出一个数据清洗预览，这份报告中说明质量问题，我们给出一个"进行转换"的摁纽，放在报告下方，如果用户点击，产出一份清洗后的lerobot格式数据即可。"

## 要做的

只改 `src/web/src`，照现有页面写法（antd、TanStack Query/Router、统一诊断组件、生成的接口类型）。

1. **数据集详情**：现在的"转换"按钮改成"清洗预览"，抽屉表单保留工具、型号、数据块三项（只列有清洗规则的型号，取工具摘要的 `cleaning_models`），去掉输出版本和空间参数（移到报告页）。提交调用 `submit_cleaning_preview_job`，成功后照现有写法跳到作业详情。说明文字一句："先只读检查数据质量，生成报告后再决定是否转换。"
2. **作业详情**：清洗预览作业成功时显示"查看清洗报告"按钮，进入报告页。
3. **报告页** `/cleaning/$jobId`（`get_cleaning_preview`）：
   - 顶部：数据集、工具、型号、生成时间；汇总（文件数、默认剔除的文件数、episode 数、默认剔除的 episode 数、保留帧 / 基准帧）。
   - 规则说明（可折叠）：对齐规则（基准话题、默认容差、断点、最短段）和数值检查规则，用报告里的值，不在前端写死数字。
   - 文件表：每个文件一行：路径、保留帧 / 基准帧、episode 数、坏帧、断点、过短丢弃、致命问题和警告；有致命问题的文件固定为"剔除"并写明原因，其余可勾选剔除。展开看每个话题的对齐统计（容差、|Δt| 平均和最大、复用、坏帧、可选缺失）。
   - episode 表：编号按**当前选择**实时算（剔除文件后后面的编号前移，和转换产物一致）；文件、帧数、时长、开始时间、问题（严重红色、提示橙色，带说明和明细），"保留 / 剔除"开关以报告默认处理为初值；被剔除文件的段灰掉、不能切换。支持只看有问题的 episode。H.264 话题显示"画面未检查"。
   - **报告最下方**："进行转换"区域：输出版本（取工具清单）、空间百分比和偏置（默认 25% 和 1 GiB；有剔除时提示"产物按两倍估算"），一句汇总"将把 N 个文件交给工具，转换后剔除 M 个 episode，产出清洗后的 LeRobot 数据集"，按钮"进行转换"→ 确认框 → 调用 `convert_from_cleaning_preview`（请求体：`output_format`、`space_ratio_percent`、`space_reserve_gib`、`excluded_files: number[]`、`excluded_episodes: {file_index, segment_index}[]`，返回作业）→ 跳到转换作业详情。只有管理员看得到按钮；剔除后没有文件或没有 episode 时按钮不可用并说明原因。
   - 选择不需要刷新后保留（不进 URL，不写本地存储）；离开页面前不用提示。
4. **转换作业详情**：阶段显示六段（含「剔除」）；有预览编号时显示"清洗报告"链接。
5. **工具库页面**：工具卡片显示有清洗规则的型号；页面上显示 LeRobot 环境状态（未配置 / 可用 / 不符及实际值）。
6. 菜单不加新项（报告从数据集详情和作业详情进入）。

## 不做

- 不改后端；不跑 `make api-types`（执行线跑）；不做报告导出。

## 允许改的受保护文件

无。

## 测试范围（只做关键测试）

1. 数据集详情：只列有清洗规则的型号；提交后调用预览接口并跳转。
2. 报告页：致命文件固定剔除且显示原因；剔除一个文件后 episode 编号前移；切换 episode 开关后汇总数字和请求体正确。
3. "进行转换"：成员看不到按钮；全部剔除时按钮不可用；管理员确认后发出正确请求并跳到作业详情。
4. 工具库页面显示 LeRobot 环境三种状态之一。

## 验收

1. tsc、ESLint、Prettier、相关 Vitest 全绿；最后一次 `make check` 全绿、0 skipped。
2. 执行线在副本环境用 Chrome 无界面截图报告页（含问题标签、底部按钮），截图放 `assets/04-report-page/`。
