## 工具的清洗做法（2026-11-09 只读核对，O_NOATIME，未在工具目录运行 git）

mcap2lerobot 的清洗只做时间对齐，不检查数值。源码：`src/sync.rs`（核心，约 100 行）、`src/verify.rs`（检查报告）、`src/convert.rs`（两遍扫描）、`src/inputs.rs`（输入展开）、`src/h264.rs`（关键帧和 B 帧判断）、`src/cdr.rs`（Header 解析）。

1. **输入展开**（`inputs.rs`）：文件原样保留；文件夹递归找扩展名为 `mcap`（不分大小写）的文件，每个文件夹内按路径排序（Rust `PathBuf` 按路径分量比较）；同一文件出现多次只留第一次（按 canonicalize 去重）；文件夹里一个都没有就报错。
2. **话题检查**：配置里的话题都要有消息；所有引用都是 `optional` 的话题在整个文件里缺失（没有消息或没有一个有效 stamp）时，用 `fill` 填满该文件所有帧，不参与对齐。消息要有 Header、编码为 cdr，否则转换报错。
3. **时间戳**：一律用 `header.stamp`（CDR：4 字节封装头后 int32 秒、uint32 纳秒、frame_id 字符串）；stamp 为 0 的不参与对齐。乱序、重复、平均频率低于 fps×0.995 只在 verify 报警告。
4. **H.264**：含 B slice 报错；第一个 IDR 之前的消息 stamp 记 0（不参与对齐），每个文件重新等关键帧。H.265 不支持。
5. **对齐与切段**（`sync.rs`，每个文件独立）：
   - 基准话题有效 stamp 排序后，每个是一帧；少于 2 个报错（整次转换失败）。
   - 其他话题取 stamp 最近的消息，距离相同取较早的；相邻帧可复用同一条消息。
   - 任一话题 |Δt| 超过容差即坏帧；话题没有有效 stamp 则所有帧都是坏帧。容差按话题取所有引用里最严格的，未写用 `sync.max_dt_ms`。
   - 坏帧处切开（首尾坏帧自然被裁掉）；基准相邻间隔 > `max_frame_gap / fps` 处切开；长度 < `min_episode_frames` 的段丢弃。
   - 保留的段按文件顺序、段顺序依次成为 episode（跨文件追加编号）。
6. R1 Lite 配置：基准是头部左目（H.264）；默认容差 10 ms，手腕相机 35 ms，夹爪目标 30 ms（约 20 Hz，左夹爪目标是可选话题，fill = 100）；`max_frame_gap = 1.6`（≈ 53 ms）；`min_episode_frames = 90`（3 秒）；fps 30。
7. 真实样本事实（M5 的 52 秒副本 `~/.cache/rdp-m5-offline/sample/r1lite_20261011_52s.mcap`，855 MB，O_NOATIME 拷自 dataset-35）：头部左右目 `h264`，手腕 `bgr8; jpeg compressed bgr8`；反馈话题约 200 Hz，夹爪目标约 20 Hz。Python `mcap` 线性读约 600 MB/s（页缓存）。

## 决定

### 1. 范围：只做 MCAP

已经是 LeRobot 的数据（含已下载的 31 个 v3.0）这次不做。只对有已登记转换工具和型号配置的 MCAP 数据集提供清洗（现在就是 mcap2lerobot + Galaxea R1 Lite）。

### 2. 复用方式：平台里用 Python 重写对齐规则，工具不改

- 新模块重写上面 1–5 条，语义逐条一致；工具自带的 Rust 测试用例（`sync.rs`、`h264.rs`、`inputs.rs` 的 tests）逐条搬成 Python 测试。
- 对齐参数只从平台登记包里的配置副本读（`tools/mcap2lerobot/configs/<型号>.toml`，工具实际用的就是这份），按工具 `config.rs` 的字段和校验解析；不另写一份参数。
- 不调用工具的 `verify` 取结果（它只出给人看的文字）。第 05 张用真实样本对照两边的 episode 和保留帧数。

### 3. 流程：先预览，再"进行转换"；没有未清洗的 LeRobot 数据

1. 数据集详情的"转换"按钮改成"清洗预览"：选工具、型号配置、数据块，提交清洗预览作业。
2. 预览作业只读输入（O_NOATIME），逐文件给出对齐结果和数值检查，报告存进数据库。
3. 报告页列出质量问题；最下方是"进行转换"按钮（输出版本、空间参数在这里填）。
4. 点"进行转换"后提交转换作业：只把预览里没被剔除的**文件**交给工具（按预览顺序逐个传文件路径）→ 工具转换到暂存 → 核对产物的 episode 和预览一致 → 有剔除的 **episode** 就用 LeRobot 的 `delete_episodes` 产出清洗后的数据集 → 原有入库检查与入库。
5. 不能绕过预览：转换作业参数必须带预览作业编号；执行时核对预览已完成、工具/型号配置/清洗规则的指纹没变、输入文件（路径、大小、mtime）没变，任何一项变了就拒绝并提示重新预览。原来直接提交转换的页面入口取消。

### 4. 剔除的粒度

- **文件级**：会让整次转换失败的文件（话题缺失、没有 Header、B 帧、H.265、基准有效 stamp 不足 2 个、解析失败、没有任何保留帧）默认剔除，不交给工具；用户也可以手动剔除整个文件。全部文件都被剔除时不能转换。
- **episode 级**：数值类问题只能整个 episode 留或删（工具不收剔除列表；`delete_episodes` 只能删整段）。逐帧裁切以后再说。
- 时间对齐类问题（坏帧、断点、短段）由工具转换时自己裁切，预览只是如实展示，与工具结果一致。
- 2026-11-10 第 07 张：episode 剔除重编码使用转换所用登记配置，逐项照工具 `config.rs` 换算编码器和参数（R1 Lite 为 GPU 的 hevc_nvenc），仅删除调用期间替换 LeRobot 编码器工厂；`info.json` 编码信息不改，实际参数写入回执 `cleaning.encoder`，没有剔除时为 `null`。

### 5. 数值检查（工具没有的，负责人"可以补上"）

每个保留的 episode 上检查，结果分"严重"（默认剔除）和"提示"（默认保留），报告里每个 episode 都能手动改成保留或剔除：

| 检查 | 规则（默认值） | 默认处理 |
|---|---|---|
| 非有限值 | 向量特征里有 NaN / ±Inf | 严重 |
| 整段静止 | `observation.state` 每一维在整个 episode 内的极差都小于该维的静止阈值 | 严重 |
| 长时间静止 | `observation.state` 连续 ≥ 3 秒逐帧变化都小于静止阈值 | 提示（列出时间段） |
| 动作跳变 | `action` 相邻帧变化大于该维的跳变阈值 | 提示（次数和首次时间） |
| 相机冻结 | JPEG/PNG/原始图话题连续 ≥ 1 秒取到的图像内容完全相同 | 提示 |
| 黑屏 / 过曝 | JPEG/PNG/原始图话题每秒抽 1 帧，平均亮度 < 10 为黑屏、> 245 为过曝 | 提示 |
| 关节超限 | 规则文件里有限位才查 | 先留空，不检查 |
| 可选话题用 fill 填充 | 工具的现有行为 | 提示 |

- 阈值按来源话题写在平台登记包的清洗规则文件里（`tools/mcap2lerobot/cleaning/<型号>.toml`，随代码评审）。R1 Lite 默认：手臂、躯干关节（弧度）静止阈值 0.001、跳变阈值 0.5；夹爪（0–100，见 docs/brief/0014）静止阈值 0.1、不查跳变（开合本来就快）。用 `fill` 填充的来源不参与静止和跳变判断。
- H.264 话题（R1 Lite 头部）不解码，不查冻结和亮度；报告里写明"H.264 画面未检查"。
- 阈值是执行线按单位定的初值，以后按真实数据再调。

### 6. LeRobot 库：直接用 conda 环境 `lerobot`

- 环境：`/home/shawn/miniconda3/envs/lerobot`，LeRobot 0.6.2，以可编辑方式安装自 `~/桌面/lerobot`（`v0.6.1-24-g6adf5151`，3 个本地改动在电机、录制、键盘输入，与数据集无关）；torch 2.10（cu126），PyAV 15.1，编码器有 `hevc_nvenc`、`h264_nvenc`、`libx265`、`libx264`、`libsvtav1`。`lerobot_v2` 目录是残留（没有解释器，conda 不认），不用也不动。
- 平台只调用它的 `lerobot.datasets.dataset_tools.delete_episodes`（v3.0 多个 episode 合在一个视频文件里，删其中一段时会用转换工具的编码器和参数重新编码混合的视频文件；只含保留段的文件原样复制）。
- 只读运行：和 M4 工具一样放进 bwrap，环境目录和源码目录只读绑定，只有本作业暂存目录可写，断网、`HF_HUB_OFFLINE=1`。平台不往这个环境里装任何东西。
- 指纹：平台登记包 `tools/lerobot/` 记下版本和平台依赖的源码（`lerobot/datasets/`、`lerobot/configs/`、`lerobot/utils/` 下全部 `.py` 合成一个 sha256）。每次运行前在沙箱里用该解释器探测实际导入的版本、位置和指纹，不符就拒绝运行，诊断"LeRobot 环境已变化，需要重新登记"。部署位置（解释器、源码目录）写在平台配置里，没配置时"有剔除的转换"不可用，没有剔除的转换不受影响。
- 环境指纹的状态显示在"工具库"页面。
