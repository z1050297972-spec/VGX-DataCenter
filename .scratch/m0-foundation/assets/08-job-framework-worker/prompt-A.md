*状态机与恢复*
- 六种状态和工单"状态机"一节的边完全一致，别的转换抛 `DefectError`。状态转换只有一个函数负责，所有写状态的地方都经过它（评审查）。
- **续跑、重跑不新增边**：上一个实例留下的"运行中"作业，按恢复方式处理：
  - 续跑、重跑：状态保持"运行中"，开始时间不变，worker 在本实例里重新执行它，执行函数从上下文里知道这是续跑还是重跑、上一次的最后进度是什么；重跑把计数清零。
  - 标记中断：运行中 → 已中断。
  - 上一个实例留下的"正在取消"：正在取消 → 已取消。
  - 每种情况都先在作业日志里追加"中断"一段：中断于哪个阶段、最后进度、处理方式；然后才改状态或重新执行。
  - 恢复的作业先于新的排队作业执行。
- **正在取消的作业最终一律是已取消**：执行函数在取消请求之后正常返回、或者抛异常，都落到已取消（没有正在取消 → 已完成 的边）。已取消和已中断保留最后进度和计数，没有作业结果。
- **只有已完成有作业结果**，由 `calculate_outcome` 从计数算出（6.8），别处不赋值。执行函数抛出的非取消异常：作业以已完成、`aborted=True` 结束（结果为失败），诊断写进作业记录，在作业执行器最外层记 ERROR（6.3）。
- **队列里出现没登记的类型、或参数按当前模型校验不过**（例如升级后类型被删）：照常 排队中 → 运行中，然后以已完成、失败结束，诊断说明原因。worker 不因此退出。

*作业类型登记*
- 登记表是一个显式对象（不是模块级可变单例），worker 和 Web 的入口各自构造并注入，测试可以注册测试专用的类型。每类登记：类型名（稳定英文键）、显示名（中文，同时作为 `logs/<作业类型>/` 的目录名，登记时校验不含 `/`、不是 `.`/`..`、长度有上限）、参数的 pydantic 模型、恢复方式、执行函数。写明参数模型里不能有口令、令牌一类字段（参数会进作业日志开头和作业记录）。
- 生产登记表本票只有"示例：数数"。

*提交、取消、重新提交（Web 端，领域服务 + 接口）*
- 任何登录账号都能提交、取消、重新提交、查看任何作业（「作业模型」Answer）。
- 提交：按登记的模型校验参数（不合格 422），插一行排队中的作业并写操作日志，同一事务。
- 取消：排队中 → 已取消，运行中 → 正在取消，状态改动和操作日志同一事务，取消人是当前账号。已经是正在取消或终态的作业：返回 409 冲突，不写日志（开始执行之前就被拒绝，同第 7 张的规则）。
- 和 worker 抢同一行的竞争（取消排队中的作业时 worker 正好在领取）：两边都用带条件的更新（`WHERE state = …`），哪边先提交算哪边，另一边按冲突处理；写清楚两种先后各自的结果并测试。
- 重新提交：只允许终态作业（已完成、已取消、已中断），新建一个作业，参数照抄，记"重新提交自 #N"，提交人是点按钮的人，写操作日志；非终态 409。
- **操作日志**：第 7 张的操作类型枚举加"提交作业""取消作业"（重新提交算提交作业，明细里带"重新提交自"）。作业不是账号，对象账号为空，作业编号、类型、前后状态按第 7 张明细 v1 的白名单写进明细；不把作业参数写进明细。前端 `OPERATION_LABELS` 相应补中文标签。

*worker（`rdp.ops` 下一个入口函数，第 11 张接命令）*
- 单实例锁：状态目录里一个锁文件，`fcntl.flock(LOCK_EX | LOCK_NB)`，进程存活期间一直持有。拿不到就返回非零退出码（具名常量），运行日志和返回信息说明"另一个 worker 正在运行"及锁文件路径。写明锁的文件描述符不被外部子进程继承（否则 worker 被杀后孤儿子进程会一直占着锁），并测试。
- 本票 worker 同一时间只执行一个作业（具名常量，注明第 9 张改为每类并发上限）。主循环约每秒一次：查取消请求、领取下一个排队中的作业（按提交顺序）。作业在线程里执行（J2），主循环、心跳不因作业执行而卡住。
- 心跳：每 5 秒写一次数据库（单行表，带实例标识、进程号、启动时间、最后心跳时间）；写失败（拿不到锁）记 WARNING、下一次再写，worker 不退出。Web 判定在线的阈值 15 秒（具名常量）；时钟回拨（最后心跳晚于现在）按经过时长 0 算，判为在线。
- 停止：给入口函数一个可注入的停止信号，测试用它在进程内停 worker；停止时的行为写清楚（不等作业跑完，留下的运行中作业由下一个实例按中断处理，和 ADR 0005"升级时重启 worker 也按中断处理"一致），所有等待有上限，线程在返回前回收。
- worker 用第 3 张的运行日志（`worker.log`），作业编号经 contextvars 带上（6.4）。

*进度*
- 执行函数通过上报对象报告：阶段（序号、总数、名称）、已完成数、总数（未知为空）、单位、警告数、失败条目数、总条目数（「可观测性」Answer）。上报对象也提供检查取消的方法，执行函数在阶段之间调用；还提供一个可被取消打断的等待（示例作业的每步间隔用它，取消后不用等满间隔）。
- 内存里总保留最新值；写数据库每秒最多一次，用 `time.monotonic()` 节流（5.4）；作业结束时写最终值。进度写入拿短锁（沿用已有的短锁具名常量或另起一个，写明多久），拿不到就跳过，下一秒再写；状态转换那一次写不能跳过，用正常的 `busy_timeout`，最终仍失败时记 ERROR，作业留在运行中，由下一个实例按中断处理。
- 总数未知时不编总数，接口返回空，页面只显示已处理多少。
- 速度和剩余时间由前端按最近约 10 秒的轮询样本算（具名常量），样本不够时不显示。

*外部进程*

*作业日志*
- 路径 `logs/<作业类型显示名>/<开始时间>.log`，在状态目录下，开始时间的格式照 ADR 0005（`2026-10-22_143015_123`），写明用 UTC 还是本地时间以及理由；同一类型同一毫秒撞名时怎么办写清楚并测试。作业记录里存相对状态目录的路径。续跑、重跑追加到同一个文件。
