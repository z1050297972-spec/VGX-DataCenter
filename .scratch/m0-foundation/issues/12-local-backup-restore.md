## 范围

1. **备份核心**（领域层，CLI 和作业共用同一组函数）：
   - 数据库用在线备份 API；
   - 导航层打成 tar.gz，软链接只存链接本身，不跟进去；排除名单来自配置；
   - 生成 `manifest.json`；
   - 先写临时目录，校验通过以后再改名；
   - 权限：文件 0600，目录 0700。
2. **配置**：新增 `[backup]` 段，各项都有默认值，旧配置不用改：
   - `directory`：默认 `<state_dir>/backups/platform`，不能和迁移前备份的目录重合；
   - `daily_at`：默认 `"03:00"`，本地时间；
   - `nav_exclude`：默认 `["解压样本", "工具", "VGX_video"]`。
3. **作业**：
   - 新作业类型 `platform_backup`，只允许管理员提交（接 M0 第 13 张的提交角色）；
   - 打包导航层期间持有导航层写锁；
   - worker 每天到点用系统身份提交一次，时钟要可控；同一天已经有成功的备份就不重复提交；
   - 成功后按保留规则清理：7 份日备份，加 4 周里每周最早的一份，只删本平台命名格式的目录。
4. **运维命令**：
   - `rdp backup`：worker 停着的时候直接执行，worker 在跑的时候提示改用作业，或者直接提交作业，两种选一种并说明理由；
   - `rdp restore <备份名> [--db] [--nav]`：
     - 只要 Web 或 worker 有一个还在跑，就拒绝；
     - 校验 sha256；
     - 数据库版本比当前代码新时拒绝；
     - 恢复前先自动备份当前状态；
     - 数据库通过临时文件原子替换，同时清掉 -wal、-shm；
     - 导航层按 ADR 的"解压到 `.rdp-restore-<时间>/`、逐个顶层目录对调、失败按相反顺序挪回去"来做；
   - `rdp backup --list`（或单独的 `rdp backups` 子命令）：列出已有备份，每行写名字、时间、大小、是否完整。
5. **页面**：作业页面能看到 `platform_backup` 作业及其结果，不另做备份页面。
6. **文档**：运维手册加一节"备份与恢复"，包括三个场景的步骤、"定期把备份目录拷到别处"的提醒、配置项说明。

## 验收

1. **关键测试**（用 tmp 目录和假导航层，不读 `/mnt`）：
   - 备份后 tar 里的链接仍然是链接，目标路径原样；排除的目录不在包里；
   - 往返一次：在假导航层上备份，然后改坏一个 JSON、删掉一条链接，执行 `rdp restore --nav`，导航层和备份时逐字节一致（链接比较目标路径）；
   - 恢复中途失败（例如注入第二个顶层目录改名失败）时，导航层保持恢复前的原样；
   - 数据库往返：恢复以后账号和作业记录回到备份时的状态；
   - Web 或 worker 在跑时 `restore` 拒绝；sha256 不对时拒绝；
   - 保留规则：给定一串日期，删掉的就是应该删的那些；
   - 定时提交：时钟拨到 03:00 以后提交一次，同一天不重复；
   - 不完整的备份目录（没有 manifest）不参与恢复、不被当成有效备份。
2. **真实演练**（执行线）：
   - 在导航层副本和临时状态目录上起服务，作业页面提交一次备份；
   - 停服，改坏副本，执行 restore，核对副本恢复如初，数据库账号还在；
   - 两块数据盘写入扇区数前后不变。
3. **检查链**：`make check` 全绿、0 skipped；变异抽查。
