# 建链与新增数据集

Status: in-progress

分级：骨架关卡。理由：新增两种写导航层的作业，以及它们给前端用的接口契约（3.0 第 1 条"跨模块接口"）。spec 原来预计"后端骨架关卡，前端页面拆成直做票并行"，这里没有拆票：前端页面在契约提交以后，作为同一张票的第二个派工并行做，占一个并行名额（3.0 第 1 条"票可以开得大一些"）。要拆的话见「待负责人确认」第 3 条。

需要负责人决定的，见「待负责人确认」第 1、2 条：**数据集名的规则**，以及**没有 `meta/info.json` 的数据块的格式和版本从哪来**。这两条定了，Status 才能改成 `ready-for-agent`。

## 依据

- M1 spec 第 08 张。
- 「软链接接口规则」（12）Answer 1A：
  - L1：建链校验；
  - L2：目的路径已存在（场景一）；
  - L3：写回 `links`/`sources`/`dataset_roots`；
  - L4：只在按任务入口建链，按格式入口勾选后生成；
  - L5：新增数据集一次建好全套；
  - L6：`dataset_id` 分配；
  - L12：预览状态。
- ADR 0005：写导航层都是作业；提交时如果已有排队的作业要改同一个数据集，网页先给一句提醒；单条建链正常 1–2 秒出结果。
- 「核心领域模型与术语」（13）、`GLOSSARY.md`：数据来源的取值（真机采集、UMI 采集、ego 采集、仿真生成、开源下载、未知）。
- 「交互形态与前端路线」（02）：成员能做全部业务操作；写操作进操作日志。
- 第 07 张：写入底座（预览、核对、原子性、恢复、变更记录、写入以后更新索引）。
- **依赖**：第 07 张合并以后开工；第 05 张合并（页面外壳）。和第 09 张不并行，两张都改写入作业。不需要新依赖。

## 目标

成员在网页上给一个数据集加一条链接，或者新增一个数据集：先看预览，确认以后由 worker 写进导航层，几秒内看到结果。

## 范围

**建链作业**（L1–L4）
- **校验**：0003 4.4 的五条，加 L1 补的四条：
  - 目标 `realpath` 后落在已登记的存储根下；
  - 目标不在导航层内部；
  - 链接名不含 `/`、不以 `.` 开头、不和入口里的四份 JSON 同名；
  - 目标不在 `dataset_roots` 之内时，预览里提示"将把 X 加进 `dataset_roots`"。
- **目的路径已存在**（L2）：拒绝，提示改走改指向。已经指向同一目标、并且登记在 `links[]` 里的，按"已经是这样了"成功，什么都不写。
- **写回**（L3）：`links[]` 追加一项。目标没被现有数据块覆盖时，追加一个数据块（`source_id` 算一次，`validation_status=path_exists_only`）。必要时追加 `dataset_roots`。
- **两个视图**（L4）：链接建在按任务入口。预览里勾选要放进哪几个按格式入口（0 到多个），这些入口由第 07 张的副本生成规则重新生成。

**新增数据集作业**（L5、L6）
- 一个作业里建好按任务入口：目录、链接、三份 JSON 的骨架、`来源.json`（数据来源必填）；再加上勾选的按格式入口。
- 骨架的内容：
  - 14 项照固定顺序写好编号和名称，`value_markdown` 留空；
  - `子任务.json` 写 `tasks: []`、`task_count: 0`。
- `dataset_id` 在写锁下分配（L6）。

**页面**（第 05 张的外壳里）
- **建链表单**：选数据集，填链接名和目标路径，勾选按格式入口。
- **新增数据集表单**：填数据集名、数据来源、第一条链接，勾选按格式入口。
- 两个表单都是：预览（将写的文件、链接、`dataset_roots` 的变化、要生成的按格式入口）→ 确认 → 看结果。
- 冲突时显示对不上的地方，提示重新预览。
- 提交时，如果已有排队的作业要改同一个数据集，先给一句提醒（ADR 0005）。

## 不做

- 改指向、撤回的页面入口：第 09 张。
- 数据来源标注：第 10 张。
- 移除数据集：见第 07 张「待负责人确认」第 4 条。
- 新数据集 14 项的内容怎么生成：地图的 Not yet specified。
- **不做（等 12 的 1B）**：链接目标或新数据集放在 NAS 存储根下，以及平台区目录布局（N4）。下载入库（M2）和转换入库（M4）复用本票"新增数据集"的规则，但不在本票做。

## 待负责人确认

1. **数据集名的规则**（挡开票）：12 的 L1 只给了链接名的规则，没有规定数据集名，而数据集名就是两个视图里的目录名。
   - 建议：和链接名同一套（不含 `/`、不以 `.` 开头），另外不能和 `按任务/` 下已有的入口重名。
2. **没有 `meta/info.json` 的数据块，格式和版本从哪来**（挡开票）：L3 写的是"`format`/`version` 来自预览时读到的 `meta/info.json`"，但 mcap 和 tar 类的数据块没有这个文件。
   - 建议：读得到就用 `meta/info.json` 的；读不到时，由提交人在预览里从格式目录登记表里选，`version` 写 `null`。
3. **前端要不要拆成单独一张直做票？** spec 原来的预计是拆。
   - 建议：不拆，同票分两个派工，免得来回交接。
