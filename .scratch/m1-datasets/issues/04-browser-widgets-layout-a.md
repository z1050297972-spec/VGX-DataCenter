## 目标

登录用户在网页上用布局 A 浏览数据集，端到端可用：看两棵树、筛选、看详情和三份 JSON、在两个视图之间跳转、看一致性面板、对单个数据集点"重新检查"。

## 范围

- **共用状态**：筛选条件、选中的数据集。放在路由的 search 参数里，或者共用的 store 里，要让第 05 张的 B、C 布局直接复用。
- **全部部件**，这张票就做全：
  - 筛选栏："更多筛选"里放型号标签；默认位置的行为按 spec 待确认第 3 条。
  - 两棵树：按格式、按任务，带数量和大小。
  - 列表。
  - 详情各块：基本信息、大小（统计值、统计时间、10-12 记录值并排）、链接状态、数据块、`validation_status` 中文标签、14 项。
  - JSON 查看器：`子任务.json` 点开才请求，在 Web Worker 里解析。
  - 跨视图跳转。
  - 一致性面板：四组两级，同类合并，带样例。
  - 存储根离线提示。
  - "索引过期"提示，带"重新扫描"按钮。
  - "重新检查"和"统计大小"按钮。
- **布局 A**：三栏，按原型接上全部部件。
- **按路由拆包**：主包压到 Vite 默认的 500 kB 警告线以下。

## 验收

1. **真实浏览器演练**（排在前半段）：第 03 张合并、本票接上真接口以后，先做演练，再补齐其余部件的测试。
   - Claude 在沙箱外起 Web 和 worker（用第 01、02 张对真实导航层只读建的索引，临时状态目录），用无头浏览器（照 M0 `demo*.mjs` 的做法）走一遍：
     - 登录，看到两棵树和 35 个数据集；
     - 按型号标签、FPS 各筛一次，数量对得上；
     - 打开 libero_10 的详情，在两个视图之间跳一次；
     - 打开最大的 `子任务.json`（约 14 MB），解析期间主线程不卡（用 Performance 记录里的长任务做判断）；
     - 看一致性面板；
     - 对一个数据集点"重新检查"，在作业页面看到它完成。
   - 截图和日志放进 assets。不写 `/mnt`。
2. **Web Worker**：用合成的 14 MB `子任务.json` 测，解析不在主线程上（Vitest 断言用的是 Worker 路径）。
3. **存储根离线**：替身数据里一个存储根离线时，顶部有提示，链接标"存储根离线"。
4. **索引过期**：接口返回"索引过期"标记时，显示提示和"重新扫描"按钮，点了会提交单数据集扫描。
5. **筛选**：型号表为空时，默认位置是型号标签筛选；有对应关系时，回到"按机器人型号"（替身数据）。
6. **拆包**：`vite build` 的主包低于 500 kB，构建输出放进 assets。
7. **检查链**：`make check` 全绿（含 Vitest）、先红后绿、变异抽查、文件归属。
