# M1.5：页面编辑、原文件查看、按场景和任务分类（决定记录）

Status: 决定已记录，待 M1 第 08–10 张合并后拆票

## 负责人原话（2026-10-30）

1. "目前我们只是把信息都展示给用户，但没有给出让用户去更改信息的功能，用户在页面的更改是直接文件中的内容"
2. "用户通过接口看不到具体的视频、info.json等原文件……比如说我想将unknown的机器人型号改成别的，目前只能在原文件更改，这就不方便"
3. "我还想按照场景和任务进行分类，这个需求和2关系很紧"

问答（执行线提问，负责人选择）：
- 型号改哪里："写导航层，不动数据盘"。
- 分类粒度："数据中心是为算法研究员服务的，能够让其快速调用目标场景和目标任务数据，我们就在数据集信息中加相应字段，并且之后的分类就按照此处的字段进行分类筛选"。
- 排期："M1 收尾后马上做（M1.5）"。

## 决定

- **编辑写导航层**：页面上的编辑改的是导航层的 `数据集信息.json`（以及已有的 `来源.json`），走第 07 张的写入底座（预览 → 确认 → 写入 → 可撤回）。数据盘只读的规矩不变。
- **机器人型号**：在 `数据集信息.json` 里加结构化字段，作为平台显示和筛选的依据；`meta/info.json` 里原来的 `robot_type` 照样显示，标明"原文件里写的是……"，两者不一致时给出提示。
- **场景和任务**：在 `数据集信息.json` 里加结构化的"场景""任务"字段，值从受控词表里选（任务可以多选）。列表、树和筛选都按这两个字段来。目的是让算法研究员能很快找到目标场景、目标任务的数据。词表的初始内容由执行线根据现有 35 个数据集第 6 项的文本起草，交负责人过目。
- **原文件查看器（只读）**：Web 可以只读存储根，并带超时（要修订 ADR 0006，以及第 03 张"接口不碰存储根"的契约），用来浏览数据块目录、查看 JSON 和文本、播放 MP4（支持 Range 请求）。只读，不提供任何写入数据盘的入口。
