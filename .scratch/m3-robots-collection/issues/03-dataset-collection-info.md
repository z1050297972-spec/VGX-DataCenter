## 契约

- **导航层**：规范副本 `数据集信息.json` 顶层新键 `collection`，按格式副本照现有流程同步：

  ```json
  "collection": {
    "status": "planned",
    "method_id": 1,
    "purpose_id": 1,
    "robot_ids": [1]
  }
  ```

  - `status`：`planned`（计划中）/ `collecting`（采集中）/ `done`（已完成），必填。
  - `method_id`、`purpose_id`：第 02 张词表的编号，可为 `null`（未填）。
  - `robot_ids`：第 01 张机器人编号数组，0–16 个，去重保序。
  - 整个键缺失或为 `null` = 这个数据集没有采集信息（开源下载等），照旧。只存编号，不存名称：改名不用改导航层。
  - 扫描读取时容错：格式不对的 `collection` 当作没有，并在一致性面板给一条提示级发现（规则码 `COLLECTION_INVALID`）；引用了不存在的编号也给提示级发现（`COLLECTION_UNKNOWN_REF`，指明哪个编号）。
- **编辑**：复用字段编辑（`nav_fields_preview` → 确认 → 写入），`数据集信息.json` 可编辑字段加"采集信息"（`collection`）。预览时校验：编号必须存在；**新选**停用的机器人或词表项被拒（原来就引用着的停用项保留不报错）。权限照字段编辑。
  - 前端编辑器：采集信息一组控件——状态（下拉，含"无采集信息"= 写 `null`）、采集方式（下拉，只列使用中的项，显示"名称（数据来源）"）、用途（下拉）、机器人（多选，只列使用中的）。选了采集方式且数据来源当前是"未知"或空时，把数据来源一并改成该方式对应的来源（在同一次预览里，用户能看到并能改回）。
- **索引**：扫描把 `collection` 投影进索引（新迁移 `0020_dataset_collection`；机器人编号用关联表），供筛选、详情和引用计数用。
- **引用计数接上**：第 01、02 张的引用数函数改为按索引计数（数据集的 `collection` 引用了这个编号就算一次）。被引用的机器人、词表项删除返回 409。
- **筛选**：`GET /api/datasets/filters` 和数据中心筛选加四个：采集状态、采集方式、用途、机器人。名称从数据库取当前名称；没有采集信息的数据集归"无采集信息"（同场景的"未标注"写法）。
- **详情**：数据集详情加"采集信息"一块：状态、采集方式（对应来源）、用途、机器人（名称，链到 `/robots`）。没有采集信息时显示"无（不是平台采集的数据集）"。
